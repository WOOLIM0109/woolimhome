# 울림 포트폴리오 목업 제작·검수 실행 계획서

작성일: 2026-09-07  
상태: 진행안 v1.6 · 묶음 1~4 합성 자료 기반 로컬 검수 완료, 묶음 5 실물 검사 진행·보류, 운영 연결 미완료  
대상: woolimhome 관리자, PC 워커, 승인된 16:9·A4 가로·A4 세로 목업

## 1. 완성 목표와 범위

새 PPT가 들어오면 원본을 검사하고, 사용할 장표를 선별하고, 필요한 부분만 가린 다음, 확정한 목업의 고정 슬롯에 배치한다. 결과는 썸네일 1장과 BODY 1~4 총 5장이다. 검사에서 실패한 결과는 완료로 넘기지 않는다.

장표를 교체해도 템플릿의 좌표·각도·여백·그림자·로고가 달라지지 않아야 한다. 이미지 재제작 때문에 기존 본문·FAQ·승인된 제목·발행 정보가 사라져서도 안 된다.

이번 계획에 포함하는 기능:

| 번호 | 기능 | 사용자가 할 수 있는 일 |
| --- | --- | --- |
| 1 | 수동 블러 편집 | 장표에서 가릴 곳을 직접 추가하거나 범위를 조절한다. |
| 2 | 슬롯 배정 미리보기 | 어떤 장표가 어느 목업의 어느 자리에 들어가는지 보고 교체한다. |
| 4 | 저해상도 초안 | 최종본 제작 전에 배치와 구성을 빠르게 확인한다. |
| 5 | 승인 템플릿만 사용 | 확정한 디자인이 없는 규격은 사유를 표시하고 보류한다. |
| 6 | 실패 단계부터 재시작 | 정상 완료한 변환·블러 작업을 살리고 필요한 단계만 다시 실행한다. |

아래의 수치와 세부 운영 규칙은 제안값이며, 기존에 확정한 시안의 좌표와 스타일을 우선한다. 묶음 1은 로컬 구현과 검수를 마쳤고 결과는 `docs/portfolio-mockup-stage-1-review.md`에 기록했다. 실제 Gemini 호출, 운영 데이터 변경, 워커 업데이트, 배포는 하지 않았다.

옛 격자형이나 다른 템플릿으로 자동 대체하는 경로가 남아 있다. 이 경로를 차단하는 작업까지 끝나야 “승인 템플릿만 사용”이 완성된다.

## 3. 전체 순서와 담당

```text
PPT 접수·작업 식별
  → 파일·폰트·규격 검사
  → 전체 장표의 저해상도 미리보기 생성 [PC 내부]
  → 사용 장표·예비 장표 선별
  → 선택 장표 고해상도 변환
  → 블러 구역 탐지·수동 수정 [PC 내부]
  → 블러 적용·검사 [PC 내부]
  → 블러본 업로드·슬롯 배정
  → 저해상도 목업 초안
  → 고해상도 목업 제작·자동 검사
  → 템플릿 변경·첫 도입·검수 요청 건: Codex 시각 검수·재작업
     일반 운영 건: 자동 검사 결과를 붙여 사용자 최종 검토로 이동
  → 최종 승인·기존 이미지 세트 교체
```

각 단계의 검사는 자동으로 수행한다. 매 단계마다 사용자에게 승인 버튼을 누르게 만들지 않는다. 일반 작업은 최종 검토 한 번으로 끝내고, 폰트 누락·규격 불일치·블러 판단 필요 등 문제가 있는 경우에 해당 편집 화면을 연다.

5~8단계에서 자동 검사 결과의 `확인 필요`가 0건이면 다음 단계로 진행한다. 불확실한 사진 속 글자·검사하지 못한 개체·공개 예외 등 확인 필요가 있을 때만 로컬 편집 화면에서 해결하도록 멈춘다. 이 예외 작업은 최종 승인 외에 중간 확인이 추가된다. 자동 탐지만으로 미탐지가 없다고 보장하지 않으며 최종 검토에서도 의심되는 부분은 다시 로컬 확인으로 돌린다.

| 담당 | 역할 |
| --- | --- |
| PC 워커 | 원본 검사, 로컬 이미지 변환·선별, 고해상도 블러, 처리 결과 저장·업로드 |
| 로컬 편집 화면 | 원본을 보며 선별 장표와 블러 영역을 확인·수정. 워커가 설치된 PC에서 사용 |
| 서버 | 작업 상태·승인 템플릿·배정안 관리, 블러본 목업 합성, 결과 검사·등록 |
| 관리자 웹 | 진행 상태, 블러본 기준 슬롯 교체와 초안 확인, 실패 단계 재시작, 최종 승인 |
| Codex | 구현·수정 시 실제 출력물을 열어 시각 검수하고 오류를 수정·재검증 |
| 사용자 | 고객 정보 공개 범위의 예외 판단과 최종 디자인 승인 |

Codex가 운영 중 모든 작업을 상시 자동으로 열어보는 기능은 현재 없다. 프로그램의 자동 검사와 Codex의 이미지 시각 검수를 별도로 기록한다. Codex가 검수하지 않은 작업을 “Codex 검수 완료”로 표시하지 않는다. 모든 작업에 Codex 검수를 원하면 해당 작업의 검수를 이 대화에서 요청하는 절차를 우선 사용한다. 별도 AI 검수 자동화는 이번 기본 범위에 넣지 않는다.

## 4. 단계별 제작 규칙

### 0단계. 승인 시안과 비교 기준 고정

- 16:9, A4 가로, A4 세로 각각 썸네일 1개·BODY 4개의 확정 시안을 모은다.
- 템플릿 ID와 버전, 출력 크기, 슬롯 좌표, 레이어 순서, 배경, 로고 파일, 그림자 값을 저장한다.
- 실제 확정된 이미지와 슬롯 번호·기준선을 표시한 검사용 이미지를 짝으로 보관한다.
- 승인 기록은 `suiteId/version`별로 원본 기준 이미지·검사용 이미지의 경로와 지문, 승인자, 승인시각을 보관한다. 전체 모아보기는 파생 자료로 구분한다. 기준 자료와 승인 기록은 `docs/portfolio-mockup-references/<suiteId>/<version>/`에 버전별로 정리하고 기존 버전을 덮어쓰지 않는다. 고객 원본이 담긴 자료는 이 경로에 커밋하지 않고 접근이 제한된 자료 위치를 참조한다.
- 상태는 `시안 → 승인됨 → 사용 중 → 이전 버전`으로 구분한다. 실제 대화에서 이미 승인한 시안은 그 승인 근거와 연결하며 같은 디자인을 다시 승인받지는 않는다. 새로운 디자인이나 좌표 변경에만 새 버전을 부여한다.
- 코드의 사용 가능 목록은 승인 기록과 지문이 일치한 버전만 참조한다. 미리보기 이미지가 있다는 이유로 승인 상태를 부여하지 않는다.
- 테스트용 장표에는 번호, 테두리, 원, 정사각형을 넣는다. 원이 타원으로 변하거나 줄이 꺾이는지 확인하기 위한 자료다.
- 묶음 1에서 세 규격 모두 썸네일 1080×1080, BODY 1600×900으로 고정했다. A4 세로 장표도 승인된 캔버스 안의 세로 슬롯을 사용하며 출력 캔버스를 임의 변경하지 않는다.

통과: 3세트 15개 모두 확정 이미지와 템플릿 정의가 연결되어 있다. 미확정·자료 누락 세트는 사용 불가로 표시한다.

현재 로컬 정의에서 계산한 슬롯 수:

| 세트 | 썸네일 | BODY 1 | BODY 2 | BODY 3 | BODY 4 | 전 슬롯 채움에 필요한 고유 장표 최소 수 |
| --- | --- | --- | --- | --- | --- | --- |
| 16:9 | 7 | 7 | 7 | 4 | 8 | 8 |
| A4 가로 | 7 | 7 | 7 | 4 | 6 | 7 |
| A4 세로 | 2 | 7 | 3 | 4 | 2 | 7 |

여기서 BODY 1~4는 사용자 화면의 순서다. 기존 코드 ID의 body-3·4·5·6과 대응표를 저장한다. 위 최소 장수는 세트 전체에서는 같은 장표를 재사용할 수 있지만, 한 목업 안에서는 중복하지 않고 모든 정의 슬롯을 채우는 경우다. 기존의 짧은 문서 통과 기준과 달라질 수 있으므로 이행 테스트에 반드시 포함한다. 최소 장수보다 적은 문서는 별도로 승인된 소수 장표용 변형이 없으면 보류한다.

초기 정책에서는 모든 정의 슬롯을 필수로 취급한다. 선택 슬롯이나 일부 슬롯 생략을 허용하려면 해당 빈자리 상태까지 확인된 별도 승인 변형과 최소 장수를 등록한다. 구현 중 임의로 선택 슬롯으로 바꾸지 않는다.

### 1단계. PPT 접수와 작업 식별

- 원본을 읽기 전용으로 열고 내용·파일명을 수정하지 않는다.
- `workId`는 같은 포트폴리오 작업을 식별하는 번호다.
- `sourceHash`는 실제 원본 파일 전체로 계산한 SHA-256 지문이다. 파일명만 바뀌고 내용이 같으면 같은 지문이며, 내용이 바뀌면 다른 지문이 된다. 암호화나 비밀키는 아니다.
- `buildId`는 이번 제작 시도에 붙이는 번호다. 오류 후 이어서 만들 때는 유지한다.
- 원본 위치, 파일 크기, 전체 장표 수, 변환기·워커 버전을 함께 기록한다. 환경변수 값이나 본문 원문을 로그에 남기지 않는다.
- 작업 도중 원본이 바뀌면 현재 제작본과 섞지 않는다. 변경을 알리고 새 제작 시도로 분리한다.

통과: 읽을 수 있는 원본과 고정된 지문, 작업 번호가 있다. 중복 실행은 같은 작업을 두 번 처리하지 않고 현재 상태를 반환한다.

### 2단계. 장수·폰트·규격 사전 검사

- 원본의 전체 장표 번호를 유지한다. 숨김 장표와 선별 제외 장표도 번호를 다시 매기지 않는다.
- 숨김·빈 장표·손상된 장표를 각각 구분한다. “제외함”과 “변환 누락”을 같은 상태로 취급하지 않는다.
- 사용 폰트를 텍스트 상자뿐 아니라 그룹·표·마스터·테마 적용 부분까지 가능한 범위에서 확인한다.
- PC 설치 폰트, 포함된 폰트의 실제 사용 가능 여부를 확인한다. 폰트 이름이 발견되었다는 이유만으로 정상 렌더링을 보장하지 않는다.
- 누락 폰트의 사용 장표 번호를 표시한다. 이 단계에서는 전체 검사 목록을 만들고, 3단계 선별 후 선택된 장표에 영향을 주는지 다시 판정한다. 선택 장표에 영향이 있으면 보류하고, 선택하지 않은 장표에만 문제가 있으면 경고를 남기고 진행할 수 있다.
- 임의 폰트 대체는 하지 않는다. 승인된 대체가 있을 때 해당 사실과 영향을 기록한다.
- 장표 안의 원·글자·표가 깨지거나 잘리는지는 고해상도 변환 후 다시 검사한다.

| 기타 | 위 분류 밖 | 규격 확인 필요로 보류 |

분류 허용 오차는 초기 제안으로 상대 오차 0.5% 이내를 사용하고 실물 파일로 조정한다. PageSetup 값과 실제 변환 이미지 비율도 대조한다. 억지 늘리기·자르기·다른 규격 템플릿 대입으로 통과시키지 않는다.

2026-09-07 후속 보완: PowerPoint A4 기본 슬라이드와 실제 종이 A4의 비율 차이를 별도로 지원한다. 모든 비슷한 규격의 허용치를 넓히는 방식은 아니다. 사용자 지정 세로 자료는 명시적 호환 미리보기로만 시험하고 기본 검사에서 계속 구분한다. 템플릿 좌표를 재제작하지 않고 원본 승인 PNG와 여백 보충 파생 입력의 관계를 기록한다. 검수 범위와 실제 PowerPoint 변환 대기 상태는 `docs/portfolio-mockup-a4-compatibility-review.md`를 따른다.

통과: 원본 번호·규격과 장표별 폰트 검사 결과를 확보했다. 파일 전체를 읽지 못하는 문제는 해결됐으며, 장표별 문제는 다음 단계의 제외·보류 판정에 전달한다.

### 3단계. 저해상도 미리보기와 장표 선별

- PC에서 전체 대상 장표를 긴 변 640~800px 수준의 미리보기로 만든다. 이것은 선별용이며 외부 업로드하지 않는다.
- 미리보기 성공·실패·명시적 제외 수의 합이 원본 장수와 맞는지 확인한다.
- 텍스트 객체와 도형 구조 정보를 선별에 함께 사용한다. 모든 장표에 고해상도 블러를 수행하지 않는다.
- 승인 세트에 필요한 슬롯 수를 먼저 계산하고, 사용할 장표와 교체용 예비 장표를 정한다.
- 이때 원본 번호 기준 임시 배정표도 만든다. 7단계에서는 블러본 검사 후 확정한 배정표로 갱신한다.
- 예비 장표는 우선 최대 2장을 준비하는 안이며 원본 장수에 맞춘다. 부족해지면 저해상도 후보 순위표에서 한 장씩 추가 처리한다. 전체 후보 수를 2장으로 제한하거나 전체 장표를 미리 고해상도 처리하지 않는다.

선별 순서:

1. 빈 화면·변환 오류·비율 불일치·숨김 장표를 제외한다.
2. 사진이나 표로 꽉 찬 장표에 관한 현재 제외 규칙을 적용하고 사유를 남긴다. 그림·차트·일러스트가 있다는 이유만으로 일괄 제외하지 않는다.
3. 동일하거나 거의 같은 장표는 대표 한 장을 우선한다.
4. 남은 후보에서 대표 장표와 보조 장표를 고른다.

“디자인이 좋은 장표” 선별 점수의 초기 제안:

| 기준 | 배점 | 판단 내용 |
| --- | --- | --- |
| 정보 위계·여백 | 25 | 제목과 핵심 내용이 구분되고 화면이 과밀하지 않은가 |
| 시각 구성 | 25 | 도표·지도·일러스트·구조화된 정보 등 디자인이 드러나는가 |
| 프로젝트 대표성 | 20 | 실제 문서 주제와 특징을 설명하는 장표인가 |
| 구성 다양성 | 15 | 이미 선택한 장표와 다른 구조·내용을 보여 주는가 |
| 가림 후 활용성 | 15 | 필요한 정보를 가린 후에도 디자인이 남는가 |

이 점수는 정답이나 객관적 미적 평가가 아니다. 자동 추천의 초기 기준이며 사용자가 교체할 수 있다. 개인정보 보호는 점수로 상쇄할 수 없는 별도 조건이다.

대표 장표는 문서 성격이 드러나고 썸네일에서 중심이 되는 장표다. 보조 장표는 대표 장표를 보완하면서 다른 구성과 정보를 보여주는 장표다. 남은 장표를 무작위로 채우는 뜻이 아니다.

중복 규칙 제안:

- 한 목업 이미지 안에서는 같은 원본 장표를 두 번 배치하지 않는다. 완전히 같은 이미지도 중복으로 본다.
- BODY 4개의 중심 장표는 가능한 한 서로 다르게 고른다.
- 썸네일에 사용한 표지를 BODY에서도 한 번 보여주는 것은 허용하되 배정안에서 표시한다.
- 세트 전체의 보조 장표 재사용은 최소화한다. 장수가 부족하면 재사용 예정과 이유를 보여준다.
- 대표 장표의 예외 외에는 아직 한 번도 사용하지 않은 적합 후보를 먼저 배정한다. 모두 사용했다면 사용 횟수가 적은 장표부터 다시 쓰며 동률은 원본 번호로 결정한다. 같은 입력이면 배정 결과도 같아야 한다.
- 한 템플릿의 필수 슬롯을 중복 없이 채울 수 없으면 보류한다. 빈 슬롯이나 무관한 다른 작업물로 채우지 않는다.

통과: 모든 후보에 선정·제외 사유가 있고 필요한 수의 장표를 확보했다. 관리자에게는 원본 번호와 대표/보조/예비 역할을 보여준다.

### 4단계. 선택 장표 고해상도 변환

- 선택한 장표와 실제 필요한 예비 장표만 고해상도 PNG로 변환한다.
- 같은 원본과 렌더링 설정으로 이미 만든 유효한 PNG는 재사용한다. 변환 전후 원본 지문을 대조해 작업 도중 원본 변경도 감지한다.
- 초기 제안은 긴 변 2400px이며, 슬롯이 필요로 하는 원본 픽셀 크기와 변환 품질을 보고 조정한다. 현재 폭 기준 변환 코드를 바꿀 때 A4 세로의 해상도를 별도로 확인한다.
- 화면비 보존, 예상 장표 번호, 파일 존재·해독, 크기, 비정상 빈 화면 여부를 확인한다.
- 잘못된 폰트·줄바꿈·표 깨짐이 있으면 이 단계에서 보류한다. 목업에 작게 넣어 가려진다고 통과시키지 않는다.

통과: 배정 후보 모두에 올바른 원본 번호와 정상 PNG가 있다. 무블러 PNG는 PC 작업 폴더에 보관한다.

### 5단계. 자동 가림 후보와 수동 블러 편집

자동 후보 탐지는 PPT 텍스트·도형 위치 정보를 우선 사용한다. 이미지 안의 글자·얼굴·서명 등은 객체 정보만으로 충분히 찾지 못하므로 로컬 탐지와 사람의 확대 확인을 보완한다. 탐지가 불확실하면 확인 필요로 남긴다.

가림 기본 분류안:

| 대상 | 기본 처리 |
| --- | --- |
| 개인 연락처·이메일·주소·식별번호·서명·계좌·인증 정보 | 내용 식별이 불가능하도록 삭제형 가림 또는 불투명 마스킹 |
| 개인 이름·얼굴, 비공개 금액·고객 목록·내부 수치·계약 상세 | 프로젝트 공개 규칙에 따라 가림. 판단 불가 시 확인 필요 |
| QR·바코드·식별 가능한 사진 속 정보 | 포함 정보가 확인되지 않았거나 공개 허용이 없으면 가림 |
| 공개가 허용된 기관명·브랜드·작업물명 | 허용 목록과 사용자 확인에 따라 유지 |
| 일반 제목·다이어그램·아이콘·장식 일러스트 | 민감 내용이 없다면 유지 |

화면 전체 블러를 기본값으로 사용하지 않는다. 넓은 영역의 가림이 필요해 디자인을 보여줄 수 없으면 다른 장표로 교체하는 방안을 먼저 제시한다.

수동 편집 화면:

- 고해상도 원본을 확대해서 볼 수 있고, 자동 가림 구역을 테두리로 표시한다.
- 사각형 추가·이동·크기 조절, 실행 취소·다시 실행, 적용 전후 비교를 지원한다.
- 장표 번호와 확대율을 항상 표시한다. 목업에서 기울어진 좌표가 아니라 원본 장표 좌표에서 수정한다.
- 좌표는 이미지 가로·세로 대비 0~1 비율로 저장하고, 장표 지문에 묶는다.
- 필수 가림의 해제는 일반 영역 삭제와 구분한다. 공개를 허용한 사람·대상 영역·사유를 기록한다.
- 편집 사항을 저장할 때 해당 장표의 블러본과 이를 사용한 목업만 재생성 대상으로 바꾼다.

로컬 처리와 관리자 웹의 관계:

- 무블러 이미지를 보며 편집하는 기능은 워커 설치 PC의 로컬 화면에서 제공한다.
- 웹의 `원본 블러 구역 수정` 동작은 로컬 편집기로 이어지고, 웹에는 완료 상태와 블러본만 전달한다.
- 다른 PC의 웹에서 원본을 보려면 별도의 원본 전달 정책이 필요하다. 기본 버전은 다른 PC에 원본을 보내지 않는다. 다른 PC에서는 블러본을 보고 추가 가림·슬롯 교체·승인을 할 수 있다.
- 로컬 편집기 연결은 먼저 작은 기술 시제품으로 검증한다. PC 재부팅, 브라우저에서 열기, 워커 오프라인, 접근 제한을 확인한다. 연결이 실패하면 `이 PC에서 편집기 열기`로 안내하고 작업은 보존한다.
- 새로 생성한 무블러 PNG 외에도 저해상도 원본 미리보기, 원문 OCR 결과, 디버그 캡처가 우회 업로드되지 않는지 확인한다. 기존 Drive 원본 보관이나 이미 서버에 있는 자료의 삭제는 별도 범위다.

통과: 사용할 장표의 필수 가림 영역과 수동 수정사항을 확정했다. 저해상도 화면만으로 작은 글씨의 공개 여부를 결정하지 않는다.

### 6단계. 블러 적용과 블러본 검사

- 원본 PNG를 덮어쓰지 않고 별도 블러본을 생성한다.
- 저장된 영역을 고해상도 좌표로 변환하고 이미지 범위 안으로 제한한다. 테두리 밖으로 글자 획이 남지 않도록 여유 영역을 더한다. 초기 제안은 긴 변 2400px 기준 4~8px이며 글자 크기에 맞춰 검증한다.
- 비밀 정보는 약한 흐림 효과만으로 처리하지 않는다. 삭제형 가림이나 불투명 마스킹 후 필요하면 주변에 부드러운 효과를 적용한다. 마스킹의 시각 스타일은 샘플에서 확인한다.
- 실제 흐림 효과를 선택한 일반 영역도 최종 출력 크기와 확대 화면에서 내용을 읽을 수 있는지 확인한다.
- 공개 출력은 단일 평면 이미지로 만들고, 무블러 썸네일·편집 레이어·원문 메타데이터를 함께 넣지 않는다.

자동 확인 항목:

- 사용 장표마다 처리 결과가 있는가.
- 원본 지문·영역 수정 버전·가림 규칙 버전이 결과와 일치하는가.
- 영역이 0 크기이거나 이미지 밖으로 벗어나지는 않았는가.
- 가림 범위와 가장자리 여유 영역 밖의 원본 디자인은 유지되는가. 회전·압축 전 PNG에서 검사한다.
- 필수 가림 영역에 실제 픽셀 처리가 되었는가. 변경이 있었음을 확인하는 것으로 내용이 안전해졌다고 단정하지 않는다.

변경된 픽셀 수를 사용자가 확인할 필요는 없다. 프로그램은 영역 적용 여부와 결과 파일 지문을 저장하며, 정확한 픽셀 수 장기 보관은 기본 요구사항으로 삼지 않는다.

프로그램이 확인 필요로 표시했을 때 사용자가 로컬에서 확인할 항목:

- 작은 이름·숫자·QR·사진 속 글자가 남지 않았는가.
- 제목·일러스트·일반 도형까지 불필요하게 가려지지는 않았는가.
- 검은 사각형이나 넓은 흐림이 디자인을 지나치게 덮는가.

개인정보 공개 판단과 무블러 원본의 정밀 확인은 로컬 절차에서 해결한다. Codex는 로컬 처리 통과 후 제공 가능한 블러본의 레이아웃·과잉 가림·경계 품질을 검수하며, 개인정보가 전혀 없다는 판정을 대신하지 않는다.

가림이 끝난 실제 블러본으로 선별 적합성을 한 번 더 확인한다. 가리기 전에는 좋았지만 가린 후 구성이 무너진 장표는 예비 장표로 교체한다. 준비된 예비가 없으면 3단계에서 새 후보를 고르고 그 장표만 4~6단계를 수행한다. 같은 후보를 계속 넣었다 빼지 않도록 제외 사유를 유지한다. 후보가 소진되면 장표 부족으로 보류하며 전체 문서를 반복 변환하지 않는다.

통과: 필수 가림 적용 검사에 합격했고 확인 필요 항목이 해소되었다. 탐지되지 않은 민감정보가 없다는 절대 보증으로 표시하지 않는다.

### 7단계. 블러본 업로드와 슬롯 배정

- 처리 완료한 블러본과 최소한의 처리 기록만 비공개 제작 저장소로 올린다. 업로드 성공 여부와 파일 해독·지문을 확인한다.
- 템플릿 버전, 슬롯 ID, 원본 장표 번호, 블러본 지문, 역할을 배정표에 저장한다.
- 배정 미리보기와 최종 렌더러가 같은 배정표를 사용한다. 최종 렌더링 때 장표를 다시 무작위 선정하지 않는다.
- 사용자는 장표를 끌어다 놓거나 선택 목록으로 교체한다. 다른 슬롯에 이미 쓰인 장표는 중복 표시한다.
- 장표 교체는 허용하지만 템플릿 좌표·각도·슬롯 크기·로고는 이 화면에서 바꾸지 않는다.
- 교체 장표에 유효한 블러본이 없으면 PC 처리 단계로 요청을 보내고, 완료 전에는 최종본을 만들지 않는다.

레이어 순서는 겹칠 때 누가 앞에 보이는지를 뜻한다. 각 템플릿에 배경, 뒤쪽 장표와 그림자, 승인된 흰색 덮개, 중앙 장표와 그림자, 로고·작업물명 순서를 명시한다. 모든 템플릿에 동일한 순서를 강제하지 않고 확정 시안의 순서를 따른다.

통과: 필수 슬롯이 모두 채워져 있고, 모두 같은 작업의 유효한 블러본이다. 승인 템플릿과 원본 규격이 맞으며 허용되지 않은 중복이 없다.

### 8단계. 저해상도 목업 초안

- 승인된 템플릿과 저장된 배정표로 초안을 만든다.
- 선형 크기 50%를 초기값으로 사용한다. 현재 캔버스 기준 썸네일 540×540, BODY 800×450이다.
- 캔버스·좌표·간격·로고·그림자까지 같은 비율로 계산한다. 고해상도 결과를 다 만든 뒤 줄이기만 하는 방식으로 속도 개선을 주장하지 않는다.
- 반올림하지 않은 하나의 기준 기하 데이터에서 초안 0.5배·최종본 1배를 각각 계산한다. 배정표 지문, 슬롯·레이어·허용 잘림 목록은 동일해야 한다. 초안 좌표를 2배 했을 때 최종 좌표와 각 꼭짓점의 차이가 최대 1px인지 검사하며, 그 이상이면 초안과 최종의 배치 불일치로 실패 처리한다. 그림자도 같은 원본 효과값에서 스케일링한다.
- 5장을 한 번에 보는 시트와 각 이미지 확대 보기를 제공한다.
- 슬롯 번호·원본 장표 번호·평행 기준선은 검토용 토글로 제공한다. 최종 공개 이미지에는 들어가지 않는다.
- 이 화면에서는 장표 선택, 크기감, 겹침, 여백, 배경, 로고를 확인한다. 블러 보안·작은 글씨·폰트의 최종 합격은 고해상도 확인 후 판정한다.

통과: 구성상 오류가 없고 배정 수정사항이 저장되었다. 일반 작업은 자동으로 다음 단계에 진행하고, 사용자가 초안 검토를 요청한 작업은 이 화면에서 대기한다.

### 9단계. 고해상도 제작과 기하·파일 검사

- 초안과 동일한 템플릿 버전·배정표·블러본으로 최종본을 만든다.
- 제목은 승인된 작업물명에서 가져온다. 업체 이름만 보고 “대기업” 등 문서 성격을 추측하지 않는다.
- 원본 장표의 글씨를 이미지 생성으로 다시 그리지 않는다. 검증된 PNG를 끼운다.
- 템플릿에 없는 검정 프레임, 빈 종이, 임의 장식, 추가 흐림 효과를 만들지 않는다.
- 승인된 로고 원본과 색상·크기·위치를 사용한다. 밝거나 어두운 배경이라는 이유로 매번 임의 변경하지 않는다.

평행·정렬 검사:

- 같은 대각선 줄의 모든 슬롯은 같은 기준축에서 좌표를 계산한다. 각 장표를 눈대중으로 개별 회전하지 않는다.
- 한 장표의 윗변과 아랫변은 평행, 왼쪽과 오른쪽 변도 평행이어야 한다.
- 같은 줄의 윗변은 하나의 직선 위에 있어야 한다. 평행하지만 서로 어긋난 상태도 실패다.
- 중앙 장표가 뒤쪽 대각선과 평행해야 하는 시안은 같은 각도를 사용한다.
- 평행이 맞아도 A4 비율이 틀릴 수 있다. 변환 전 원본 비율과 고정된 변환 방식도 별도로 확인한다.
- 일반 회전 슬롯은 원본 비율을 보존하며 비균일 늘리기나 사다리꼴 변형을 금지한다.
- 세로 BODY 4처럼 기울어진 평면 표현을 사용하는 경우 승인된 변환 하나를 모든 관련 장표에 공유한다. 네 모서리를 각각 임의 수정하지 않는다. 승인된 시각 효과 외의 추가 찌그러짐을 검사한다.
- 가장자리 장표가 일부 잘리는 것은 템플릿에서 허용한 슬롯에만 적용한다. 중심 장표의 제목·로고·필수 내용 잘림은 실패다.

초기 자동검사 허용치 제안:

| 검사 | 초기 통과 조건 |
| --- | --- |
| 좌표 계산의 평행·같은 줄 정렬 | 수학적 정의에서 일치. 출력 반올림을 별도 처리 |
| 렌더 이미지의 기준선 편차 | 최종 해상도에서 최대 1px. 그림자·안티앨리어싱 경계는 구분 |
| 승인 시안 대비 여백·간격 | 고정 좌표와 일치. 캔버스 반올림 1px 이내 |
| 원본 가로세로 비율 | 비균일 크기 변경 없음. 픽셀 반올림만 허용 |
| 완성 파일 | 썸네일 1개·서로 다른 BODY 템플릿 4개, 각 파일 해독 가능 |
| 장표·작업 식별 | 모든 슬롯이 승인한 배정표 및 같은 workId·buildId와 일치 |
| 가림 | 모든 입력 이미지의 가림 버전과 처리 기록 유효 |

허용치는 실제 이미지로 검증해 확정한다. 전체 픽셀 완전 일치만으로 검사하지 않는다. 이미지 라이브러리의 작은 렌더링 차이와 실제 배치 오류를 구분해야 한다.

통과: 수학적 정렬과 결과 이미지 검사를 모두 통과했다. 파일이 만들어졌거나 테스트가 통과했다는 이유만으로 시각 검수까지 완료 처리하지 않는다.

### 10단계. Codex 시각 검수와 재작업

개발·템플릿 수정 시에는 해당 세트 전체를 Codex가 실제로 열어 본다. 운영 작업은 시각검수 요청을 받은 결과에 적용하며, 요청 전까지 자동 검사 결과만 표시한다.

검수 자료:

1. 확정 시안과 같은 장표로 만든 비교용 결과.
2. 새 작업물로 만든 썸네일·BODY 4장 전체.
3. 슬롯 번호·기준선·레이어 순서를 표시한 검토용 이미지.
4. 선택 장표의 블러본과 로컬 검수 결과. 실제 고객 원본/블러본 비교는 사용자가 로컬 편집기에서 수행한다. Codex의 비교 시험에는 비식별 테스트 장표를 사용한다.
5. 장표 배정표, 자동 검사 결과, 현재 원본·템플릿·블러 수정 버전.

검수 순서:

| 순서 | Codex가 실제로 확인할 것 | 실패하면 돌아갈 단계 |
| --- | --- | --- |
| A | 5장을 모아 보고 전체 밀도·색감·장표 다양성·세트 일관성 확인 | 선별 또는 배정 |
| B | 5장을 각각 열어 정렬·윗변 연결·평행·여백·그림자·중앙 장표 앞뒤 순서 확인 | 템플릿 구현 또는 렌더 |
| C | 로컬 처리 통과 후 고해상도 블러본에서 제목·폰트·로고·과잉 가림·가림 경계 품질 확인. 개인정보 확인은 로컬 검수 기록 확인 | 변환 또는 블러 |
| D | 원본 장표 번호와 배정표를 대조해 누락·중복·다른 작업물 혼입 확인 | 배정 |
| E | 관리자 미리보기와 내려받은 최종 파일이 같은 결과인지 확인 | 저장·등록 |
| F | 기존 본문·FAQ·제목·발행 정보와 이미지 삽입 위치가 보존됐는지 확인 | 이미지 교체 연동 |

판정은 `합격`, `수정 필요`, `확인 불가` 세 가지다. 이미지를 열지 못했거나 필요한 확대 자료가 없으면 합격으로 쓰지 않는다. 사람 이름·고객 수치의 공개 허용 여부처럼 외관으로 판단할 수 없는 문제는 사용자 확인 필요로 남긴다.

“로컬 파일을 Codex로 연다”는 것이 원본 픽셀을 PC 밖으로 보내지 않는다는 뜻은 아니다. 따라서 기본 검수에서 Codex에 실제 무블러 원본·원본 캡처를 전달하지 않는다. 블러본조차 외부 모델에 제공할 수 없는 작업은 로컬 사용자 시각검수로 대체하고 Codex 확인 불가를 정확히 표시한다.

템플릿 변경·첫 도입・사용자 요청 건은 Codex의 시각검수 완료가 해당 작업의 통과 조건이다. 일반 운영 건은 `자동 검사 통과 / Codex 시각검수 미실시`로 정확히 표시하고 사용자 최종 승인으로 진행할 수 있다.

수정 요청에는 `BODY 번호 / 슬롯 / 원본 장표 번호 / 문제 / 기대하는 상태`를 기록한다. 예: `BODY 4 / 오른쪽 장표 / 12쪽 / 두 장의 윗변이 한 직선에서 어긋남 / 동일 기준축에 맞춰 배치`.

수정 후 영향받은 단계의 자동검사를 다시 실행하고 해당 이미지를 다시 연다. 공통 템플릿 계산이나 로고·그림자를 고쳤으면 그 세트의 5장 전체를 다시 검수한다. 두 차례 같은 자동 재작업을 해도 해결되지 않으면 원인과 비교 이미지를 남겨 보류한다. 승인 시안을 임의로 새 디자인으로 바꾸며 반복하지 않는다.

최종 검수 기록에는 작업/제작 번호, 확인한 파일 지문, 템플릿·가림 버전, 검사 종류, 검수자, 시간, 결과를 저장한다. 이후 이미지가 바뀌면 해당 시각검수 완료 기록은 새 파일에 승계하지 않는다.

### 11단계. 최종 승인·결과 교체·연동 확인

- 사용자는 썸네일과 BODY 4장, 필요한 주의사항을 한 화면에서 보고 승인한다.
- 일부만 만들어진 세트로 기존 정상 이미지들을 덮어쓰지 않는다. 새 세트와 검증 기록을 모두 준비한 후 현재 활성 이미지 세트를 바꾼다.
- DB와 파일 저장소 사이에 단일 트랜잭션이 있다고 가정하지 않는다. 파일 업로드 후 목록을 검증하고 DB의 활성 세대 포인터를 조건부로 교체한다. 뒤따르는 동기화는 같은 ID로 다시 실행해도 중복이 생기지 않게 한다.
- 관리자·검토 요청·외주 작업실이 같은 새 이미지 세트를 가리키는지 확인한다. 한 화면에만 옛 자료가 남으면 완료로 표시하지 않는다.
- 기존 본문·FAQ·승인된 제목·게시글 URL·발행 상태를 보존한다. 이미지 연결 영역만 갱신한다.
- 이미지 재제작으로 글 생성 작업이나 Gemini 검수를 자동 시작하지 않는다. 새 본문 작성은 기존 별도 작업으로 둔다.
- 이전 정상 세트는 복구 가능한 상태로 보존한다. 관리자가 `이전 이미지로 되돌리기`를 실행하면 해당 세트로 복원한다.
- 최종 목업 승인과 네이버 블로그 게시 완료는 다른 상태다. 이 기능이 게시글을 새로 발행하거나 기존 발행 URL을 바꾸지는 않는다.

통과: 저장된 5장과 모든 관련 화면의 연결이 일치하고, 본문과 발행 정보가 유지됐다. 사용자 승인 후에도 오류가 발견되면 기존 세트로 복구할 수 있다.

## 5. 관리자에게 보일 화면

작업물 목록은 기본 접힘 상태를 유지한다. 작업물명, 규격, 현재 단계, 마지막 오류, 확인 필요 여부로 정렬·필터한다.

작업을 펼치면 다음 영역을 보여준다.

| 화면 | 주요 내용·동작 |
| --- | --- |
| 진행 상태 | 현재 단계, 완료한 수/대상 수, 워커 연결 상태, 실패 원인 |
| 장표 선택 | 선택·예비·제외 목록과 이유. 원본 열기는 워커 PC에서 제공 |
| 블러 수정 | 이 PC에서 로컬 편집기 열기. 웹에는 상태와 처리된 블러본만 표시 |
| 목업 배정 | 썸네일·BODY 1~4, 슬롯 번호, 원본 장표 번호, 교체 동작 |
| 결과 검토 | 저해상도/최종본 구분, 자동 검사 결과, 실제 수행된 시각 검수 결과 |
| 작업 동작 | 실패 단계부터 재시작, 원인 해결 후 재검사, 최종 승인, 이전 세트 복구 |

사용자 화면의 일반 상태는 `원본 확인 → 장표 준비 → 블러 확인 → 목업 제작 → 최종 검토 → 완료`로 간단히 보인다. 내부의 해시·버전·체크포인트는 필요할 때 펼치는 진단 영역에만 표시한다.

다른 PC의 웹에서 `추가 가림`을 지정하면 좌표 요청을 워커에 보내 재처리한다. 웹에서 즉시 원본을 불러오거나 블러를 해제하지 않는다. 재처리 완료 전에는 새 승인본으로 전환하지 않는다.

## 6. 재시작과 재사용 규칙

“캐시”는 이미 정상 처리한 중간 파일을 보관했다가 다시 쓰는 것이다. 예를 들어 8쪽의 블러가 끝났고 BODY 3에서만 렌더링이 실패하면 8쪽을 다시 변환·블러하지 않는다.

재사용 키는 원본 지문 하나로 끝내지 않는다. 작업 ID, 원본/장표 지문, 변환 설정·폰트 환경, 가림 규칙·수동 수정 버전, 템플릿 버전, 배정표를 단계별로 확인한다. 다른 고객 작업의 결과를 가져다 쓰지 않는다.

| 변경·실패 | 유지할 수 있는 결과 | 다시 할 일 |
| --- | --- | --- |
| 업로드 실패 | 검증된 로컬 블러본 | 실패한 파일의 업로드·이후 검사 |
| BODY 3만 렌더 실패 | 선택·블러·나머지 유효한 파일 | BODY 3 렌더·최종 세트 검사 |
| 슬롯 배정만 변경 | 기존의 유효한 블러 장표 | 영향받은 목업 초안·최종 렌더·시각검수 |
| 한 장표의 블러 수정 | 다른 장표의 처리본 | 수정 장표 블러·그 장표를 쓰는 모든 목업·검수 |
| 새 장표 선택 | 기존의 유효한 선택 장표 | 새 장표의 변환·블러와 영향받는 목업 |
| 템플릿 수정 | 유효한 변환·블러본 | 배정 적합성 검사·해당 세트 렌더·검수 |
| 원본 또는 폰트/변환 환경 변경 | 참고용 옛 결과만 보존 | 관련 변환부터 새로 검증. 이전 승인 승계 금지 |
| 가림 정책 강화 | 원본 변환본 | 가림부터 다시 적용·검수 |
| 등록 후 화면 동기화 실패 | 완성 이미지 세트 | 누락된 연결 동기화만 재실행 |
| PC 재부팅·워커 중단 | 디스크·DB에 저장한 완료 단계 | 파일 지문을 확인하고 미완료 단계부터 재개 |

단계 완료는 임시 파일 저장, 해독/지문 확인, 완료 기록 저장 순서로 처리한다. 중간 파일을 완료 파일로 읽지 않게 하고, 작업을 두 워커가 동시에 처리하지 못하게 소유권·제작 번호를 검사한다. 만료된 작업 소유권을 복구할 때도 파일을 먼저 검증한다.

전송·스토리지의 일시 오류는 자동 재시도 최대 1회를 초기안으로 두고 이후 사용자 재시작을 기다린다. 규격·폰트·가림·정렬 오류는 그대로 반복해도 해결되지 않으므로 자동 반복하지 않는다. 외부 AI 호출 재시도는 이 목업 재시작에 포함하지 않는다.

중간파일 정리는 작업 ID별 보관 정책을 별도로 설정한다. 활성 세트, 수동 승인 자료, 다른 작업 폴더, 원본 자료는 자동 정리 대상에서 제외한다. 기존 서버 원본을 삭제하는 이행 작업은 필요 대상과 복구 방법을 정한 후 별도 처리한다.

새로 생성하는 무블러 PNG·OCR 임시 결과·원본 디버그 조각은 원본 PPT와 구분한다. 워커의 작업별 접근 제한 폴더에 두고 OneDrive 등 동기화 폴더 밖에 생성한다. 초기 보관안은 최종 승인·작업 취소 후 24시간, 진행 중 또는 실패 작업은 마지막 활동 후 7일이다. 만료가 다가오면 알리고, 만료 후에는 이 buildId가 만든 임시 파생파일만 정리해 결과를 기록한다. 정리 실패는 경고로 남긴다. 재개에 필요한 파생파일이 없으면 원본에서 해당 단계부터 재생성하며 원본 PPT는 삭제하지 않는다.

## 7. 다섯 덩어리로 나누는 실행 순서

사용자가 확인할 작업 단위는 아래 5개다. 각 묶음 안에서 구현, 필요한 자동검사, Codex의 실제 결과 확인, 오류 수정과 재확인까지 마친다. 묶음별로 결과를 보여주고 진행 상태를 기록한다. 같은 확정 디자인을 다시 승인받는 절차는 추가하지 않는다.

현재 묶음 1~4는 각 검수 문서의 합성 자료·로컬 범위에서 완료됐다. 묶음 5에서는 새 장표 요청의 명시적 로컬 처리, 최종 이미지 전달·본문 보존의 대역 검사와 실제 PPT 3개 검사를 진행했다. 실제 가림 단계의 오탐과 A4 규격 불일치로 최종 목업까지 도달하지 못했다. 실제 저장소 업로드, 요청 자동 실행, 운영 화면·워커·인증 연결은 미완료다. 전체 기능 완료나 운영 배포 완료가 아니며 각 묶음의 검수 문서에 기록한 제한을 따른다.

| 순서 | 작업 묶음 | 사용자에게 보여줄 결과 | 끝났다고 판단할 기준 |
| --- | --- | --- | --- |
| 1 | 목업 틀 고정 | 3규격 × 썸네일·BODY 4종, 총 15개 출력과 기준선 비교 | 장표를 바꿔도 좌표·평행·여백·로고가 유지됨 |
| 2 | PPT 준비와 작업 기록 | 원본 검사 결과, 장표 선정·제외표, 진행 단계 표시 | 선택한 장표만 고해상도 변환되고 중단 후 작업 기록 복원 가능 |
| 3 | 자동·수동 블러 | 가짜 개인정보 샘플의 편집 화면과 처리 전후 비교 | 직접 지정한 영역이 정확히 가려지고 PC에서는 블러본만 업로드 |
| 4 | 장표 배정과 미리보기 | 장표 교체 화면, 저해상도 초안, 고해상도 최종본 | 같은 배정표로 두 결과가 나오며 교체한 자리만 의도대로 바뀜 |
| 5 | 전체 연결과 실사용 검수 | 처음부터 끝까지 처리한 실제 사례, 이미지 교체·실패 복구 결과 | 본문 보존·관련 화면 일치·재시작·복구까지 검증 후 제한 적용 |

### 묶음 1. 목업 틀 고정

- 16:9와 A4 가로의 기존 구현·변경 사항을 확인해 이어서 사용한다.
- 확정한 A4 세로 시안을 정식 좌표 템플릿으로 등록한다.
- 확정 이미지와 대화의 승인 근거를 먼저 연결한다. 확인되지 않은 시안이 있다면 그 부분만 미확정으로 남기며, 모든 시안을 새로 승인받지는 않는다.
- 3세트 각각 썸네일 1개·BODY 4개를 버전으로 고정한다. 승인 목록 밖 템플릿은 새 경로에서 사용하지 못하게 한다.
- 템플릿별 필수 슬롯 수·필요한 최소 장표 수·장표 재사용 규칙도 이 묶음에서 고정한다. 묶음 2의 선별기는 이 정의를 그대로 읽는다.
- 번호·테두리·원·정사각형이 들어간 시험 장표를 끼워 15개를 만든다.
- Codex가 15개를 실제로 열어 윗변 연결·평행·비율·여백·로고·그림자를 확인하고 잘못된 계산을 수정한다.

이 묶음의 완료물은 고정 템플릿과 검수한 15개 예시다. PPT 전체 자동 처리나 운영 이미지 교체는 후속 묶음에서 연결한다.

2026-09-07 완료: 관련 테스트 100개·lint·타입 검사, 15개 실제 이미지와 교체 모아보기 검수 통과. 제목 과대 확대와 세로 BODY 1 로고 겹침을 보정했다. 구체적인 좌표 보정과 운영 격리는 `docs/portfolio-mockup-stage-1-review.md`를 따른다.

### 묶음 2. PPT 준비와 작업 기록

- 작업 ID, 원본 지문, 제작 시도 번호와 단계별 입출력·수정 버전 규칙을 먼저 정한다.
- 완료 단계 저장·복원, 소유권 확인, 이전 정상 결과 보존의 공통 구조를 만든다. 재시작 기반을 마지막 통합 단계까지 미루지 않는다.
- 제작 중인 세트와 현재 사용 중인 세트를 서로 다른 ID·참조로 관리한다. 이미 완료한 세대를 덮어쓰지 않는 저장 구조부터 마련하고, 최종 교체·되돌리기 화면은 묶음 5에서 연결한다.
- 폰트·장수·규격 검사, 전체 저해상도 후보 생성, 장표 선별, 선택 장표만 고해상도 변환을 연결한다.
- 선정·제외·보류 사유와 원본 번호를 표시한다.
- 무블러 이미지를 서버에 보내지 않은 채 로컬 편집기를 여는 연결 시제품을 검증한다.
- 변환 도중 중단·PC 재시작·선별 변경을 시험하고 단계 기록이 맞는지 Codex가 확인한다. 원본 시각 확인이 필요한 시험은 비식별 자료로 수행한다.

이 묶음의 완료물은 준비된 장표와 읽을 수 있는 선정표·진행 기록이다. 고해상도 무블러 장표는 PC 안에 남는다.

2026-09-07 로컬 완료: 준비 경로 51개·고정 템플릿 회귀 14개 테스트, 타입·lint 검사 통과. 실제 PowerPoint에서 합성 16:9 8장과 A4 가로/세로 각 1장을 변환하고 고해상도 10개를 개별 시각 검수했다. 새 경로는 PPTX 전용이며 미확정 글꼴/개체를 보류한다. 로컬 확인은 읽기 전용 시제품이다. 실제 PC 재부팅·고객 원본·운영 서버 연결은 이번에 수행하지 않았다.

### 묶음 3. 자동·수동 블러

- 3A: 자동 가림 구역, PC 내 고해상도 가림, 가림 결과 검증과 블러본 업로드를 만든다.
- 3B: 로컬 편집기에서 영역 추가·이동·크기 조절·실행 취소·저장과 공개 예외 기록을 연결한다.
- 수동 수정 버전이 바뀌면 해당 장표의 처리 결과부터 다시 검증한다.
- 가림 후 디자인이 무너진 장표는 후보표로 돌아가 새 장표 하나만 준비한다.
- 가짜 이름·번호·QR 등의 샘플로 좌표, 누락·과잉 가림, 고해상도 적용, 재시작을 검증한다.
- Codex는 비식별 샘플과 로컬 검사를 통과한 제공 가능한 블러본을 검수한다. 실제 원본의 공개 판단은 로컬 사용자 절차를 따른다.

가장 작업량이 큰 묶음이므로 3A 결과와 3B 화면을 각각 보여준다. 운영 연결 전 두 부분이 모두 통과해야 한다.

2026-09-07 로컬 완료: 준비·가림 경로 83개와 고정 템플릿 회귀 14개, 총 97개 테스트 및 타입·lint 검사 통과. 3규격 합성 개인정보 샘플의 처리본과 실제 로컬 편집 UI를 검수했다. 실제 저장소 대신 주입한 대역으로 승인된 단일 평면 PNG만 전송됨을 검증했다. 픽셀 OCR/얼굴 인식 엔진, 운영 업로드와 기존 워커 교체는 연결하지 않았다. 좌표·추출 결과가 불완전하면 수동 확인 체크만으로 넘기지 않고 장표 교체/원본 정리 후 재변환을 요구한다. 상세 범위는 묶음 3 검수 문서에 기록했다.

### 묶음 4. 장표 배정과 미리보기

- 썸네일·BODY별 슬롯 번호와 원본 장표 번호를 보여준다.
- 장표 교체, 중복/부족 장표 표시, 새 장표 준비 요청을 연결한다.
- 하나의 배정표와 기준 좌표로 저해상도 초안과 최종본을 만든다.
- 초안과 최종본의 기하 배치, 레이어, 그림자, 허용 잘림을 대조한다.
- 배정 수정 후 영향을 받는 목업만 다시 만들고, Codex가 바뀐 이미지와 세트 모아보기를 확인한다.

테스트용 블러본으로 화면 개발 일부를 앞당길 수 있지만, 실제 전체 흐름의 합격은 묶음 3의 가림 결과와 연결한 뒤 판정한다.

2026-09-07 로컬 완료: 합성 장표를 실제 묶음 3 가림·승인 서비스로 처리한 뒤, 승인된 PNG와 승인 지문을 확인해 묶음 4 배정·제작 서비스로 연결했다. 관련 테스트 112개, 타입 검사와 lint를 통과했다(lint는 기존 경고 1개). 세 규격 최종 15장·모아보기 3개·기준선 예시 3개를 실제로 열어 검수했다. 브라우저에서 중복 차단, 저장 중 편집 잠금, BODY 3 장표 교체와 재생성을 확인했으며 나머지 4개 최종 파일의 지문은 그대로였다. 교체된 결과와 새 모아보기도 다시 검수했다. 새 장표 준비 요청은 로컬 기록까지이며 자동 처리 실행은 묶음 5에서 연결한다. 운영 업로드·배포·기존 활성 이미지 변경은 하지 않았다. 상세 증거와 제한은 묶음 4 검수 문서를 따른다.

### 묶음 5. 전체 연결과 실사용 검수

- 원본 접수부터 최종 검토까지 전 단계를 연결한다.
- 묶음 4의 새 장표 준비 요청을 실제 선택 장표 변환·가림·승인 흐름에 연결한다. 현재 요청 기록만으로 워커를 자동 실행하지 않는다.
- 템플릿 버전이 바뀐 제작 시도는 기존 출력 사용을 차단한 상태에서, 명시적인 새 배정/새 제작 시도 전환 절차를 제공한다.
- 단계별 오류와 중복 실행을 강제로 재현해 필요한 부분만 재처리되는지 확인한다.
- 새 세트가 완성된 뒤 이미지 연결만 교체하고 본문·FAQ·제목·발행 정보를 대조한다.
- 관리자·검토 요청·외주 작업실·다운로드 결과가 같은 세트를 가리키는지 확인한다.
- 최초 제안 표본은 규격별 2개, 총 6개였다. 2026-09-07 사용자 지시에 따라 이번 검수는 일반 PPT 10개 중 무작위 1개와 A4 가로·세로 각 1개, 총 3개로 한정한다. 제공 가능한 최종 결과 15장을 실제로 열어 검수한다. 외부 모델 제공이 불가한 자료는 로컬 사용자 시각검수로 구분해 기록한다.
- 검수한 서버·워커 버전 조합으로 일부 작업부터 적용하고, 이전 이미지 복구를 확인한다. 운영 적용 권한과 준비가 갖춰진 시점에 진행한다.

이 묶음까지 통과해야 전체 기능을 완료로 표시한다. 앞선 묶음의 완료를 전체 구현·운영 배포 완료로 표현하지 않는다.

2026-09-07 중간 검수: 관련 테스트 142개와 타입 검사를 통과했다. 실제 16:9 원본은 12장 중 사진·표 밀집 2장을 제외한 10장 고해상도 변환에 성공했지만 가림 탐지 불확실성으로 보류됐다. 실제 A4 가로·세로는 기준 비율 상대 오차 약 2.13%·0.82%로 변환 전 보류됐다. PowerPoint 구역 목록의 참조를 실제 장표로 중복 집계하던 오류를 수정했다. 본문·FAQ·제목·발행 정보 보존은 메모리 대역으로 검증했으며 운영 DB·관련 화면에 대한 전체 검증은 아니다. 실제 최종 출력 시각 검수, 승인 인증, 기존 이미지 저장 경로 통합, 첫 기존 세트 복구와 운영 연결이 남았다. 운영 배포·워커 업데이트는 하지 않았다. 상세 판정은 `docs/portfolio-mockup-stage-5-review.md`를 따른다.

### 묶음별 공통 보고

매번 `만든 기능 / 직접 확인할 결과 / 자동검사 및 Codex 시각검수 결과 / 남은 문제 / 다음 묶음`을 짧게 보고한다. 완료한 변경은 다른 묶음과 구분해 검토·되돌리기 가능한 단위로 관리한다. 실패하면 수정 후 해당 검사를 반복하고, 해결되지 않은 필수 문제를 다음 묶음의 완료로 숨기지 않는다.

모든 묶음의 개발·테스트는 실제 Gemini 호출 없이 진행한다. 작업 ID·장표 ID·영역 수정 버전의 약속은 묶음 2에서 정해 이후 화면과 워커가 함께 사용한다.

## 8. 테스트와 검수 표

자동화 테스트에는 가짜 원본·가짜 가림 대상·로컬 저장소 대역을 우선 사용한다. 실제 Gemini 등 유료 API는 호출하지 않는다. 외부 호출 함수를 대역으로 바꾸고 호출 시도가 발생하면 테스트 실패로 잡는다.

| 분야 | 시험할 상황 | 합격 조건 |
| --- | --- | --- |
| 기본 출력 | 3규격 × 썸네일/BODY 4개 | 총 15개가 각각 승인 시안과 맞음 |
| 장표 수 | 짧은 문서, 충분한 문서, 슬롯보다 적은 문서 | 정상 출력 또는 정확한 부족 사유. 빈 장표 생성 없음 |
| 번호 | 숨김·제외·변환 실패 장표 포함 | 원본 번호 유지, 각 상태 설명, 누락 은폐 없음 |
| 규격 | 16:9/A4 가로/A4 세로/4:3/경계값 | 올바른 세트 또는 명시 보류. 늘리기 없음 |
| 폰트 | 한글·영문·표·마스터·그룹·누락 폰트 | 선택 장표의 깨짐 보류, 정상 글자와 원본 대조 |
| 선별 | 사진/표 밀집·지도·차트·일러스트·중복 | 현재 제외 기준 준수, 이유 표시, 수동 교체 가능 |
| 블러 | 작은 글씨·사진 속 글자·QR·서명·계좌 등 가짜 자료 | 필요한 가림 적용. 일반 제목/그림 유지 |
| 수동 편집 | 확대/축소·영역 이동·취소·저장·동시 편집 | 고해상도 위치 일치, 수정 충돌 감지, 오래된 결과 차단 |
| 정렬 | 같은 대각선 줄·중앙 장표·A4 세로 BODY 4 | 평행과 같은 직선 정렬 모두 충족 |
| 스타일 | 밝고 어두운 장표, 긴 작업물명 | 고정 배경/로고 유지, 제목 넘침과 겹침 없음 |
| 배정 | 중복 장표·예비 장표 교체·미처리 장표 선택 | 중복 차단/표시, 필요한 부분 처리 후 렌더 |
| 재개 | 변환·블러·업로드·렌더·DB 동기화 중 실패 | 완료 단계 보존, 실패 부분 재처리, 중복 파일/행 없음 |
| 동시성 | 중복 클릭·워커 2개·PC 재부팅 | 한 제작 시도 소유권 유지, 이전 시도 결과 혼입 없음 |
| 변경 감지 | 원본·폰트·가림 규칙·수동 영역·템플릿 변경 | 필요한 후속 결과와 승인만 무효화 |
| 웹 연동 | 관리자·검토요청·외주·다운로드 | 같은 최종 이미지 세트, 캐시로 옛 자료 잔존 없음 |
| 본문 보존 | 기존 본문/FAQ/제목/URL 있는 작업 이미지 교체 | 이미지 연결 외 데이터 동일, 원고 재생성 호출 없음 |
| 비용 | 수정·저장·미리보기·재시작·배포 | 이 목업 처리에서 유료 AI 호출 0회 |
| 개인정보 경로 | 업로드 요청·로그·진단·임시 미리보기 | 무블러 PNG/원문/비밀값의 신규 외부 전달 없음 |

테스트 명령은 구현 변경에 맞춰 선정한다. 저장소 lint·타입 검사와 관련 테스트를 통과한 뒤 실제 렌더 이미지 검수를 수행한다. 이미지 영역 교체만 변경했는데 본문 재작성 결과까지 달라졌다면 회귀 오류로 다룬다.

권장 실물 검수 표본은 규격별 최소 2개 문서, 총 6개다. 하나는 일반적인 구성, 하나는 해당 규격의 까다로운 구성으로 고른다. 사용할 원본의 접근·공개 범위가 확인되지 않으면 합성 샘플로 해당 문제를 먼저 재현한다.

## 9. 도입·복구 방식

1. 기존 로컬 수정 목록을 기록하고 이번 구현 범위와 겹치는 부분을 통합한다. 임의 초기화·덮어쓰기를 하지 않는다.
2. 새 처리 경로는 테스트 모드와 일부 지정 작업에서 먼저 사용한다. 이때 기존 정상 결과와 본문은 유지한다.
3. 서버와 워커가 지원 기능·버전을 확인한다. 새 경로를 지원하지 않는 워커에는 새 작업을 배정하지 않고 업데이트 필요를 표시한다.
4. 작업 대기 중인 새 버전 적용과 진행 중인 작업의 버전 고정을 구분한다. 제작 중간에 규칙이나 템플릿을 갈아끼우지 않는다.
5. 3규격의 첫 실물 결과는 Codex가 5장씩 모두 열어 보고 검수 기록을 남긴다. 이후 사용자에게 결과를 보여준다.
6. 제한 적용에서 문제가 없으면 새 작업으로 적용 범위를 늘린다. 기존 완료 작업 전체를 자동 재제작하지 않는다.
7. 문제가 생기면 새 작업을 멈추고 기존 정상 세트를 유지한다. 실패 제작 시도의 파일·오류·상태를 남겨 원인을 재현한다.

프리뷰 환경에서는 데이터·스토리지·워커 큐를 운영과 분리한다. 운영 작업을 개발 워커가 가져가거나 개발 결과를 외주 작업실에 노출하지 않는다. Gemini 환경변수와 비용 상한은 이 목업 기능을 위해 변경하지 않는다.

## 10. 최종 납품물과 완료 기준

납품물:

- 승인된 3세트 15개 템플릿 정의와 비교용 기준 이미지.
- 장표 접수·선별·변환·가림·배정·제작의 단계별 실행 기능.
- 로컬 블러 편집기와 관리자 슬롯/초안/최종 검토 화면.
- 재시작·중복 실행 방지·이전 정상 이미지 복구 기능.
- 테스트 결과와 Codex가 실제 확인한 이미지별 검수 기록.
- 실패 단계·사유·다음 동작을 설명하는 짧은 운영 안내.

완료로 인정하는 조건:

1. 세 규격 모두 장표만 교체했을 때 승인된 배치와 효과가 유지된다.
2. 사용하지 않을 전체 고해상도 장표를 불필요하게 블러하지 않는다.
3. 새로 만든 무블러 장표 이미지가 PC 밖으로 업로드되지 않는다.
4. 사용자가 블러 구역과 장표 배정을 수정할 수 있고 결과가 정확히 반영된다.
5. 저해상도 초안과 고해상도 최종본의 기하 배치가 같다.
6. 잘못된 결과는 사유와 함께 멈추며 이전 정상 결과를 덮어쓰지 않는다.
7. 실패 단계 재개와 각 규칙 변경 후 재검증이 실제 시험에서 작동한다.
8. 본문·FAQ·제목·발행 정보를 보존하고 관련 화면을 일치시킨다.
9. 자동 검사와 실제 수행된 Codex 시각 검수가 각각 확인 가능하다. 템플릿 변경·첫 도입·요청 건은 Codex 검수가 완료돼야 하며, 일반 운영 건은 미실시 상태를 숨기지 않는다.
10. 구현·테스트에 실제 Gemini 호출이 없고, 목업 수정 자체가 새 AI 과금을 만들지 않는다. Codex 사용량은 별개다.
