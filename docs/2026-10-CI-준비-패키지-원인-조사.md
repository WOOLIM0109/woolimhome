# Linux 준비 런타임 패키징 실패 원인과 수정 제안

2026-10-17. 조사 브랜치는 `fix/ci-preparation-package`, 기준은 `main`의 `750e38f2c521c274181f9fce0a796875096629e6`이다. 이 문서는 조사 결과이며 패키징 구현·보안 검사·CI 설정·의존성은 변경하지 않았다.

## PR #146 마무리

[PR #146](https://github.com/WOOLIM0109/woolimhome/pull/146)은 `eadebc9dd7a589fd561c6ccab2f596b30ad2ecfa`까지 보고서를 반영하고 draft 상태로 대표 검토를 기다린다. CI 패키징 실패 9건은 해당 PR에서 수정하지 않는다. 마지막 Windows `npm run verify`는 1,003 통과·실패 0이다. 운영 병합·배포·마이그레이션·삭제·과거 이력 적재·첫 제작은 실행하지 않았다.

포트폴리오의 dry-run 목록, 백업·과거 이력 CSV 경로와 승인 순서는 [해당 브랜치의 최종 보고서](https://github.com/WOOLIM0109/woolimhome/blob/eadebc9dd7a589fd561c6ccab2f596b30ad2ecfa/docs/2026-10-포트폴리오-자동화-수정.md)에 남겼다. 정리 후에만 가능한 작업 7 미리보기는 아직 실행하지 않았다.

## 확인된 원인

거부된 파일은 다음 npm 실행 파일 링크다.

```text
node_modules/sharp/node_modules/.bin/semver
  -> ../semver/bin/semver.js
```

`sharp@0.35.3`은 `semver@^7.8.5`에 의존한다. 잠금 파일과 실제 설치 결과 모두 `node_modules/sharp/node_modules/semver`에 `7.8.5`를 두며, 이 패키지의 `bin.semver`는 `bin/semver.js`다. Linux npm 설치가 위 링크를 만들었다. 링크 대상은 같은 체크아웃의 정규 파일이며 `nlink=1`이다.

`scripts/preparation-runtime-package.mjs:205`는 각 의존성에 대해 `await tree(directory)`를 먼저 끝낸 다음, 207행에서 `node_modules/`로 시작하는 결과를 제외한다. 그런데 `tree()`는 120행에서 심볼릭 링크를 즉시 거부한다. 따라서 원래 복사 대상에서 제외할 `sharp/node_modules/.bin/semver`에 먼저 도달해 `PREPARATION_PACKAGE_UNSAFE_FILE`이 발생한다. 제외 조건이 재귀 순회보다 늦게 적용되는 것이 직접 원인이다.

`runtime-package.test.mjs:21`의 공통 준비 훅이 패키징을 실행하므로, 준비 훅 하나의 실패가 9개 테스트 전체의 `hookFailed`로 나타난다. 9개의 개별 검증 조건이 각각 실패한 것은 아니다.

Windows에서 동일 경로는 심볼릭 링크가 아닌 389바이트 실행 래퍼였다. 따라서 순회 중 링크 거부를 만나지 않고 뒤의 제외 조건까지 도달한다. npm은 기본적으로 Unix 계열에서는 실행 파일 링크를, Windows에서는 `.cmd` 래퍼를 만든다고 명시한다. [npm 공식 bin-links 설명](https://docs.npmjs.com/cli/v10/using-npm/config/#bin-links), [package.json bin 설명](https://docs.npmjs.com/cli/v10/configuring-npm/package-json/#bin).

소스와 잠금 파일 해시는 로컬 기준 브랜치와 Linux에서 일치했다. 실제 GitHub CI는 `ubuntu-latest`와 Node 22이므로 배포판까지 동일한 재현은 아니다. 다만 원본 코드의 같은 행·같은 오류·같은 준비 훅 실패를 Linux에서 재현하고, 거부 경로까지 직접 관찰했다. 기존 [main CI](https://github.com/WOOLIM0109/woolimhome/actions/runs/36023512982)와 [PR CI](https://github.com/WOOLIM0109/woolimhome/actions/runs/38962227065)의 9건 실패와 일치한다.

진단용 Sandbox는 조사 후 종료했다. 테스트 성공을 만들기 위한 링크 삭제, `--no-bin-links`, 보안 검사 우회, 테스트 생략은 수행하지 않았다. 수정안을 적용한 테스트는 아직 실행하지 않았으므로 수정 후 9건 통과를 주장하지 않는다.

조사 보고서 커밋 전 Windows에서 기준 브랜치의 `npm run verify`를 실행해 타입·린트와 984개 테스트가 모두 통과했다 (`.codex-tmp/verify-ci-preparation-report.log`). 포트폴리오 변경을 포함한 PR #146의 1,003개와 기준 브랜치의 984개는 서로 다른 코드 범위다. 이 Windows 성공은 Linux 실패가 해결됐다는 의미가 아니다.

## 제안하는 수정 범위 — 아직 미적용

1. **의존성 수집 시에만**, 각 패키지 루트의 실제 `node_modules` 디렉터리를 재귀 진입 전에 제외한다. 심볼릭 링크 여부·비정상 파일 종류 검사는 제외 판단 전에 유지한다. 모든 깊이에서 이름만 보고 디렉터리를 무시하는 규칙은 사용하지 않는다.
2. 하위 패키지는 기존 `dependencyRecords()`가 잠금 파일과 실제 버전을 검증한 명시적 의존성 목록으로 별도 수집한다. 따라서 `sharp/node_modules/semver` 본체는 계속 포함되고 `.bin` 래퍼는 포함되지 않는다.
3. 완성된 패키지를 확인하는 `inspectPreparationRuntime()`의 `tree(root)`에는 위 제외 규칙을 적용하지 않는다. 출력물 전체 파일 목록·해시·신뢰 지문 검사를 유지한다. 수집 대상 파일·상위 경로의 링크 거부, `nlink=1`, `.env` 거부, 파일 수·용량 제한도 유지한다.
4. 변경 예상 파일은 `scripts/preparation-runtime-package.mjs`와 `lib/pc-worker/preparation/runtime-package.test.mjs`다. CI 운영체제 변경, 의존성 버전 변경, 전역 링크 허용은 제안하지 않는다.

이 제안은 기존에 제외하도록 정한 경로를 순회하기 전에 제외하도록 순서를 고친다. Linux 링크를 허용하거나 대상 파일을 따라 복사하는 방식은 필요하지 않다.
