# 관리자 목업·제목 편집 운영 연결 검수

## 배포 전 검수 기록

이 문서는 운영 배포 직전의 검수 기록이다. 2026-09-07 검수 종료 때에는 운영 DB 마이그레이션, git push, Vercel Production 배포, 설치된 PC 워커 교체를 하지 않았다. 2026-09-13 로그인 및 DB 반영 결과는 아래 마지막 절에 추가했다. 로컬 검수 통과만을 배포 완료로 해석하지 않는다.

당시 Supabase 서비스 역할의 기존 데이터 조회는 가능했지만, DB 스키마 변경용 CLI 로그인/직접 DB 자격 증명이 없어 사용자에게 로그인을 요청했다. 토큰·환경변수 값은 로그/원고/커밋에 기록하지 않는다. Vercel의 기존 woolim-site 프로젝트와 Node.js 24.x 설정은 읽기 전용으로 확인했다.

## 연결 방식

- 관리자 요청은 별도 `portfolio_mockup_sessions`에만 기록한다. 본문 생성 큐나 기존 원고 상태를 변경하지 않는다.
- PC는 명시적으로 요청된 세션만 준비한다. 원본 PPT와 무블러 장표는 PC의 비공개 폴더에 유지한다.
- 로컬 블러/배치/제목 검토 후 검증된 목업 PNG 5장과 검증된 제목 없는 썸네일 바탕만 immutable 경로로 업로드한다.
- 업로드된 후보는 바로 사용하지 않는다. 서버가 실제 저장 PNG의 해시/규격/평탄화 및 고정 템플릿 증명을 재검사한다.
- 관리자가 5장을 열어 확인하고 확정해야 원자적 DB 함수로 현재 이미지 세트를 교체한다.
- 제목만 편집할 때는 검증된 바탕 PNG를 재사용한다. PPT 변환·본문 목업 재생성·Gemini 호출을 하지 않는다.
- 제목 후보도 별도 저장하며 확대 확인과 명시적 적용을 구분한다. 입력 또는 원고 리비전이 달라지면 이전 후보를 적용할 수 없다.
- 편집 연결 만료 시 별도 재연결 요청으로 일회용 로컬 링크만 다시 발급한다. 재다운로드·재변환은 하지 않는다.

## 보존 및 오류 경계

- 전체 이미지 교체는 정확히 대응되는 BODY 4장의 src만 바꾼다. 기존 HTML 위치·문장·캡션·FAQ·게시글 제목·발행 URL/상태·일정·기타 메타데이터는 유지한다.
- BODY가 3장/5장이거나 중복 src/srcset 등 대응이 모호하면 자동 재배치하지 않고 중단한다.
- 제목 교체는 썸네일 행/포인터만 바꾼다. BODY 행 ID·URL·본문 HTML은 변경하지 않는다.
- DB 변경은 리비전/전체 메타데이터/활성 포인터 비교 후 한 트랜잭션으로 실행한다. 중간 실패 시 일부 이미지만 활성화되는 결과가 없다.
- 이전 세트와 제목 버전, 원본 이미지 이력은 보존한다. 레거시 복원 함수도 최신 원고를 유지하고 이미지 바인딩만 복원하도록 제한했다. 복원 UI는 이번에 추가하지 않았다.
- 레거시 업로드·재생성·복원·하드코딩 이미지 교정은 활성 검증 세트를 덮을 수 없다.
- 기존 정리 정책은 검증 세트/제목/세션 이력이 있는 원고의 본문·이미지·원본·download 작업 증거를 삭제하지 않는다. 보존 이력 테이블이 없거나 손상 포인터가 있으면 삭제를 차단한다.
- 새 세트의 발행 검증도 출처/고정 템플릿/슬롯/현재 블러 규칙/본문 figure·URL을 확인한다. 기존 원고 품질 검사는 계속 실행한다.
- PC 구 워커와 새 준비 작업은 PowerPoint 공유 잠금을 사용한다. 설치된 워커는 운영 준비가 끝나기 전에 바꾸지 않는다.

- 실제 PostgreSQL 호환 인메모리 엔진에서 4개 마이그레이션 및 실제 RPC 19개 검사 통과. SQL CASE 구문 오류를 수정한 뒤 다시 통과했다.
- 마지막 JSONB 수정까지 반영한 `npm.cmd run verify`에서 typecheck/lint와 전체 테스트 979/979 통과(실패·건너뜀 0). 최종 Production 빌드도 77개 페이지 생성까지 다시 통과했다. 관리자 UI·준비 검토 UI·워커 경계 별도 검사 51/51 및 마지막 스냅샷·DB 경계 통합 검사 54/54도 통과했다. 새 코드의 미사용 변수 경고는 정리했다. 기존 홈페이지 이미지 관련 lint 경고 1개는 이번 범위에서 변경하지 않았다.
- 실제 관리자 React 컴포넌트를 합성 데이터 전용 서버에서 확인했다. 외부 fetch를 막았으며 입력 중 요청 0회, 5장 개별 확인, 제목 후보 생성·확정 분리, 문구 변경 후 이전 후보 차단, 오류 시 입력/기존 이미지 유지, 교체 영수증을 확인했다.
- 기존 실제 PPT 검수 자료 325개 해시 일치, 누락/이미지 변경 0. 달라진 build 기록 3개는 제목 편집 이력 추가뿐이며 기존 아티팩트 변경/삭제 0.
- 세 가지 규격의 서버 제목 렌더 결과는 기존 로컬 렌더의 픽셀과 일치했다.

- 보류 상태에서도 규격/추상 그래픽 후보의 비공개 원본을 명시적으로 준비해 실제 크기로 확인할 수 있다. 사유와 개별 확인을 받은 결정만 새 임시 작업에 적용한다. 실패하면 기존 작업 폴더/편집 결과를 그대로 유지하며, 블러나 운영 적용을 자동 승인하지 않는다.

- 최종 감사에서 PostgreSQL JSONB가 객체 키 순서를 바꾸면 정상 스냅샷 해시/제목 검증이 실패하는 문제를 발견했다. 전송용 스냅샷만 재귀 정렬 해시로 통일하고, 고정 템플릿·렌더·제목 manifest·BODY 캐시 fingerprint는 변경하지 않았다. 실제 로컬 PGlite JSONB 저장·조회 후 stage→세트 확정 RPC→발행 검증→제목 후보 확정→발행 검증 6/6을 통과했다. 이전 순서 의존 스냅샷은 안전하게 거부하며 새 미리보기에서 새 해시를 받는다.
- 최종 PC 런타임 패키지 188개 파일/6개 의존성/38개 모듈의 해시와 import graph를 검증했다. Sharp PNG 생성, XML 로딩, launcher `--check` 통과. 워커 시작/설치는 하지 않았다. 패키지 fingerprint: `c03b127e493faaaff7ab618dd8f7ce27c9cfd51415ac95ce580e0a65763dc5f0`.

## 운영 반영 순서

1. 최종 전체 verify 및 빌드, 최신 PC 런타임 패키지 무결성 재검사.
2. 인증된 기존 Supabase 프로젝트에 새 마이그레이션만 적용하고 스키마/RPC 가용성을 읽기 전용으로 확인.
3. 승인된 코드·템플릿·테스트·문서만 커밋/푸시. 환경 파일·원본 PPT·무블러 PNG·임시 자료는 제외.
4. 올바른 woolim-site Production 배포와 Ready 상태/커밋/URL 확인.
5. 사무실 워커가 실제 작업 중이 아닌지 확인 후 현재 설치본을 보관하고 버전 2.10.0과 새 고정 런타임을 설치/시작. 시스템 실행 정책은 바꾸지 않는다.
6. 인증/상태/화면의 비파괴 점검만 진행한다. 실제 고객 자료의 공개 승인, 본문 재생성, Gemini 테스트 호출은 하지 않는다.

사용자 또는 운영자가 실제 완성 목업을 확인하기 전에는 로컬 기술 검수 기록을 발행 승인으로 바꾸지 않는다.

## 2026-09-13 로그인 후 배포 직전 확인

- 사용자의 CLI 로그인 완료 후 기존 Woolim 프로젝트를 다시 확인했다. 별도 프로젝트/계정/토큰을 만들지 않았다.
- 현재 코드로 verify(typecheck/lint/lib tests 981/981), 관리자 UI 12/12, Production build 77/77을 다시 통과했다. 주요 API 배포 trace의 비공개 환경 파일/임시 QA/PPT/PDF 포함은 0이고 필수 렌더 자산 누락도 0이다.
- 네 마이그레이션 원문을 순서대로 한 트랜잭션에서 실행했다. 운영 적용 전 같은 합본을 fresh 로컬 PGlite에서 검증했고, 원고/이미지/발행 이벤트/작업 데이터의 전후 해시가 바뀌면 트랜잭션 전체가 실패하도록 했다.
- 운영 DB에서 `MIGRATIONS_APPLIED` 수신. 기존 원고 69행, 이미지 정보 14행, 발행 이벤트 33행, 작업 4행이 모두 `unchanged=true`였다. 새 6개 테이블이 REST에서도 조회 가능하며 RLS와 공개 접근 차단을 확인했다. 기존 원고를 승인·재생성하거나 이미지를 교체하는 RPC는 호출하지 않았다.
- 기존 DB에 CLI migration-history 테이블이 없어서 과거 이력을 임의 작성하지 않았다. 이번에는 이 저장소의 정확한 네 SQL을 Management API 기반 CLI query로 적용했다. 향후 일괄 `db push` 전에 과거 수동 적용 이력을 별도 대조해야 한다.
- woolim-site는 GitHub의 woolimhome/main에 연결되어 있고 자동 배포가 활성화돼 있다. 커밋은 감사한 기능 파일만 포함하며 환경 파일·CLI 임시 자료·원본 PPT는 제외한다.
