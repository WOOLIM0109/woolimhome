# NAVER WORKS 연결이 시작한 주소로 돌아오게 하고, 토큰 갱신 오류를 분명하게 만든다

작업 폴더: `C:/dev/woolimhome/.codex-tmp/works-redirect` (브랜치 `fix/works-oauth-redirect-host-20261107`)

## 지금 무슨 일이 일어나고 있나

대표가 `https://www.woolimcompany.kr/admin/sources` 에서 「NAVER WORKS 다시 연결」을 누르면 연결이 끊긴다.
끝나는 주소가 `https://woolim-site.vercel.app/admin/sources?works=invalid_state` 다.

이유는 이렇다.

1. `app/api/admin/naver-works/connect/route.ts` 가 확인표(state)를 쿠키로 저장한다.
   쿠키는 요청이 온 주소(`www.woolimcompany.kr`)에만 저장된다.
2. `lib/naver-works/client.ts` 의 `oauthRedirectUri()` 가 환경변수 `NAVER_WORKS_REDIRECT_URI` 하나만 본다.
   그 값이 `https://woolim-site.vercel.app/api/admin/naver-works/callback` 이다.
3. NAVER WORKS 는 로그인 뒤 그 vercel 주소로 되돌려 보낸다.
4. `app/api/admin/naver-works/callback/route.ts` 가 쿠키를 찾는데, 주소가 달라서 쿠키가 따라오지 않는다.
   `expectedState` 가 없어 `invalid_state` 로 끝난다.

두 주소 모두 NAVER WORKS 개발자 콘솔에 Redirect URL 로 등록을 마쳤다. 등록 작업은 더 할 것이 없다.

- `https://woolim-site.vercel.app/api/admin/naver-works/callback`
- `https://www.woolimcompany.kr/api/admin/naver-works/callback`

그리고 운영 DB 에 이런 오류가 남아 있다.

```
The "data" argument must be of type string or an instance of Buffer, TypedArray, or DataView. Received undefined
```

`refreshConnection()` 안에서 `encryptToken(token.access_token)` 이 불릴 때
`token.access_token` 이 없으면 나는 오류다. 무엇이 잘못됐는지 사람이 읽을 수 없다.

## 할 일 A — 연결을 시작한 주소로 돌아오게 한다

`lib/naver-works/client.ts`

- `oauthRedirectUri()` 가 요청 주소를 받을 수 있게 한다. 예: `oauthRedirectUri(request?: Request)`
- 요청의 host 가 아래 허용 목록에 있으면, 그 주소의 `/api/admin/naver-works/callback` 을 돌려준다.
  - `www.woolimcompany.kr`
  - `woolimcompany.kr`
  - `woolim-site.vercel.app`
- 허용 목록에 없거나 요청이 없으면 지금 그대로 둔다.
  `NAVER_WORKS_REDIRECT_URI` → `NEXT_PUBLIC_SITE_URL` → `https://woolim-site.vercel.app` 순서.
- 허용 목록은 반드시 코드 안에 둔다. Host 헤더는 바깥에서 고칠 수 있는 값이라 그대로 믿으면 안 된다.
  목록에 없는 host 는 조용히 기본값으로 떨어뜨린다.
- 프로토콜은 항상 `https` 로 맞춘다.

`authorizationUrl()` 과 `exchangeAuthorizationCode()` 가 **같은 값**을 쓰게 요청을 넘긴다.
두 곳이 다른 값을 쓰면 토큰 교환이 그 자리에서 실패한다.

- `authorizationUrl(state, request)`
- `exchangeAuthorizationCode(code, connectedBy, request)`

부르는 곳은 두 군데뿐이다.

- `app/api/admin/naver-works/connect/route.ts`
- `app/api/admin/naver-works/callback/route.ts`

`connect/route.ts` 의 `GET()` 은 지금 인자가 없다. `GET(request: NextRequest)` 로 바꿔서 넘긴다.

## 할 일 B — 토큰 갱신 오류를 분명하게 만든다

`lib/naver-works/client.ts`

- `tokenRequest()` 가 돌려준 값에 `access_token` 이 비어 있으면(없거나 문자열이 아니면)
  그 자리에서 한국어 오류를 던진다.
  예: `NAVER WORKS가 Access Token을 돌려주지 않았습니다. 다시 연결해 주세요.`
- `refreshConnection()` 과 `exchangeAuthorizationCode()` 둘 다 이 보호를 받아야 한다.
- `exchangeAuthorizationCode()` 의 기존 Refresh Token 확인은 그대로 둔다.

## 검사

`lib/naver-works/token-refresh.test.mjs` 에 더한다. 이미 `client.ts` 를 VM 으로 실제 실행하는 틀이 있으니 그것을 쓴다.

1. 갱신 응답이 200 인데 `access_token` 이 없을 때
   - 한국어 오류 문구가 나온다
   - 연결 기록이 `expired` 로 남는다
   - `The "data" argument` 같은 문구는 나오지 않는다
2. `oauthRedirectUri()` 가
   - `https://www.woolimcompany.kr/...` 요청이면 www callback 을 돌려준다
   - `https://woolim-site.vercel.app/...` 요청이면 vercel callback 을 돌려준다
   - 모르는 host 요청이면 환경변수 값을 돌려준다
   - 요청이 없으면 환경변수 값을 돌려준다
3. `authorizationUrl(state, request)` 이 만든 주소의 `redirect_uri` 가
   같은 요청으로 구한 `oauthRedirectUri(request)` 와 글자 그대로 같다

끝나면 `npm run verify` 를 돌리고, 실패한 검사 이름과 오류 원문을
`docs/codex-tasks-2026-11-07/01-works-redirect-results.txt` 에 적는다.

## 지키는 선

- `.codex-tmp/` 안의 다른 폴더는 건드리지 않는다
- 환경변수 이름을 바꾸거나 지우지 않는다. `NAVER_WORKS_REDIRECT_URI` 는 그대로 남는다
- SQL·마이그레이션 파일은 건드리지 않는다
- `lib/program-review/` 등 이 작업과 상관없는 폴더는 건드리지 않는다
- 쿠키의 `path`, `httpOnly`, `sameSite` 설정은 지금 그대로 둔다
- Client ID·Secret 등 비밀값을 코드나 문서에 적지 않는다
