# 가림 편집기를 설치할 수 있게 만든다

설계는 이미 있다. **`docs/codex-tasks-2026-10-28/01_준비런타임_사무실PC_설치.md` 의
「작업 B」와 「작업 C」를 읽고 그대로 한다.** 아래는 그 둘만 하라는 범위와 주의다.

## 왜 지금 하는가

변환 워커(`worker.ps1`)는 설치본이 저장소에 있어서 PC 몇 대든 `setup.ps1` 한 번으로
깔리고, 켜질 때마다 스스로 최신 코드를 받아 갈아끼운다.

가림 편집기는 그게 없다. 띄우는 파일 두 개(`launch-hidden.vbs`,
`mockup-bridge-launch.ps1`)와 예약 작업이 **2026-09-22 에 사무실 PC에서 손으로
만들어진 것**이고 저장소에 없다. 런타임 경로와 지문이 그 파일에 글자 그대로 박혀 있다.

그래서 두 가지가 막힌다.

- 직원 PC에 **얹을 물건이 없다**
- 새 버전이 나올 때마다 **사람이 그 파일에 지문을 손으로 박아야 한다**
  (2026-11-08 하루에만 두 번 했다)

## 이번에 하는 것

10-28 문서의 **작업 B 전체**와 **작업 C 전체**. 작업 A 와 작업 D 는 하지 않는다.

- **작업 B** — `bridge-launch.ps1`, `launch-hidden.vbs`, `bridge-install.ps1` 을
  `tools/woolim-pc-worker/` 에 넣는다. 경로·지문은 파일에 박지 않고
  `%LOCALAPPDATA%\WoolimWorker\bridge-runtime.json` 에서 읽는다.
- **작업 C** — `bridge-update.ps1`, `bridge-update.cmd`,
  `approved-preparation-runtimes.json`. 더블클릭 한 번으로
  패키지 → 지문 대조 → 설치 → 전환 → 결과 확인, 실패하면 되돌리기.

10-28 문서에 적힌 순서·검사·한국어 문구·되돌리기를 그대로 따른다.
그 문서가 정한 것을 새로 설계하지 않는다.

## 승인 목록의 첫 항목

`approved-preparation-runtimes.json` 의 `win32/x64` 최신 항목에 이 지문을 넣는다.

```
0dd37af3825d72c564dfe28846a5282cfeba41b15b624fbf43e47d42425020cd
```

2026-11-08 에 PR #224 병합 직후 main 에서 만든 꾸러미의 지문이고,
지금 사무실 PC가 돌리고 있는 것과 같다. 버전은 `1.0.0`.

## 건드리지 말 것

10-28 문서의 「공통 지키는 것」을 그대로 지킨다. 특히 이 파일들은 **수정 금지**다.

```
scripts/*preparation*        scripts/run-*.mjs        scripts/install-*.mjs
lib/pc-worker/preparation/*  tools/woolim-pc-worker/prepare-slides.ps1
tools/woolim-pc-worker/worker.ps1                     tools/woolim-pc-worker/install.ps1
```

`scripts/preparation-runtime-package.mjs` 의 `PREPARATION_RUNTIME_SOURCE_FILES` 에
**새 파일을 넣지 않는다.** 넣으면 꾸러미 지문이 바뀌어 위에 적은 승인 지문과 어긋난다.

사무실 PC의 기존 파일을 지우지 않는다. 설치 스크립트가 덮어쓸 때는 10-28 문서대로
`%LOCALAPPDATA%\WoolimWorker\_replaced\<날짜시각>\` 로 복사해 두고 덮는다.

비밀키는 읽지도, 인수로 넘기지도, 화면에 내지도 않는다.

바뀌었으면 수정 금지 파일을 건드린 것이므로, 되돌리고 보고한다.
