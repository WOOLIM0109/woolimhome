# 현대실업 다운로드 오류 진단 기록

기존 기록의 `curl 22`만으로는 401·403·404·5xx 중 원인을 확정할 수 없다. 이번 변경은 다음 실패 때 구분할 수 있도록 PC 워커 다운로드 로그와 최종 오류에 HTTP 상태, 최종 호스트, 요청 식별자의 SHA-256을 남긴다. 과거 실패 원인을 특정했다고 보고하지 않는다.

curl의 write-out은 메모리에서만 처리하며 전체 URL·경로·쿼리·사용자 정보·Authorization·응답 본문·원본 요청 ID는 로그에 남기지 않는다. 원본 stderr도 출력하지 않는다. 허용한 네 개 메타데이터 줄만 최대 8 KiB로 처리하고, 요청 ID는 각각 최대 256자 및 제어 문자 없음 조건을 확인한 뒤 해시로 기록한다. 파싱할 수 없는 정보는 `unknown` 또는 `none`으로 남긴다. 기록 예시는 `curl=22 http=403 host=example.test request_id_sha256=<해시>`다.

기존 외부 다운로드 3회, 대기 2·4초, curl 내부 재시도 2회, 연결·전체 제한 시간, `--fail`, 리디렉션 처리는 유지한다. 인증 갱신이나 보안 우회, 무제한 재시도는 추가하지 않는다. 헤더 write-out을 지원하지 않는 구형 curl에서는 요청 ID가 없을 수 있으며, 이를 성공이나 인증 오류로 추정하지 않는다. 검증 PC의 curl은 8.21.0이다. 옵션 근거: [curl 공식 매뉴얼](https://curl.se/docs/manpage.html).

워커 버전은 `2.10.2`다. 흥국생명 글꼴 PR과 각각 main에서 분기했으므로 두 번째 PR을 병합할 때 최신 main 반영과 최종 워커 버전 재확인이 필요하다. 실행 중인 워커와 별도 worktree에서 작업했으며 운영 설치·재시작·현대실업 원본 재다운로드는 하지 않았다. 운영 후보는 수정 승인 전까지 `excluded`로 유지한다.

## 검증

- 다운로드 테스트 5건과 기존 워커 잠금 테스트 3건, 총 8건 통과. PowerShell 함수만 AST로 추출하여 워커 시작이나 운영 API 호출 없이 검사했다.
- 로컬 HTTP 서버와 실제 curl로 401·403·404, 302→403, 200 성공을 확인했다. 실패별 외부 시도 3회와 성공 시도 1회, 별도 mock으로 대기 2·4초 및 기존 옵션 유지를 확인했다.
- 가짜 URL 서명·사용자 정보·Authorization·응답 본문·원본 요청 ID가 로그와 반환 오류에 포함되지 않는지 확인했다. 잘못된 입력·길이 초과 시 원문을 출력하지 않는 것도 검사했다.
- 새 테스트 중 PowerShell 실행 4건은 Windows에서 실제 실행하며 Ubuntu에서는 환경 전용 테스트로 생략한다. 소스 연결 검사 1건은 양쪽에서 실행한다.
- 실제 현대실업 원본의 다운로드 성공이나 과거 HTTP 응답은 확인하지 않았다. 배포 후 사용자가 재시도를 승인하면 새 진단 기록으로 원인을 좁힐 수 있다.
- 커밋 전 Windows `npm run verify`: 타입·린트 통과, 1,015 통과·Unix 전용 5 생략·실패 0. 로그: `.codex-tmp/verify-download-diagnostics.log`. 실제 유료 API는 호출하지 않았다.
