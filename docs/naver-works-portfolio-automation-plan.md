# NAVER WORKS Drive 기반 포트폴리오 완전 자동화 계획서

작성일: 2026-07-27  
대상: 울림컴퍼니 디자인 블로그 포트폴리오 자동화

## 1. 목표

대표자 PC가 꺼져 있어도 서버가 NAVER WORKS Drive의 지정 프로젝트 폴더를 탐색하고, 기존 블로그와 중복되지 않는 프로젝트를 선정하여 포트폴리오 초안과 이미지를 제작한 뒤 관리자 검토 요청에 비공개로 등록한다.

자동화의 마지막 단계는 항상 `검토 필요`이며 네이버 블로그에 자동 공개하지 않는다.

## 2. 확정된 운영 규칙

- Drive는 읽기 전용으로 연결한다. 원본 파일을 수정·이동·삭제하지 않는다.
- 대표자가 PPT·PDF를 개별적으로 찾지 않는다.
- 프로젝트 폴더 단위로 분석하고, 기존 디자인 블로그와 중복된 프로젝트는 제외한다.
- 연락처, 주소, 사업자번호, 개인 이름 등 민감정보를 우선 탐지한다.
- 폰트가 누락되거나 변환 결과가 깨지면 초안을 발행 후보로 만들지 않고 보류한다.
- 대표 썸네일 1장, 메인 콜라주 목업 1장, 본문용 가로 목업 약 3장을 기본 제작물로 한다.
- 본문 이미지는 관련 문단 바로 다음에 배치하며 상단에 몰아서 나열하지 않는다.
- 동일한 형식이나 내용을 반복한 이미지는 사용하지 않는다.
- 모든 결과물은 `검토 필요` 상태로 관리자 페이지에 등록한다.

## 3. 전체 처리 흐름

```text
NAVER WORKS OAuth 연결
→ 지정 폴더 재귀 탐색
→ 신규·수정 파일 색인
→ PPT·PPTX·PDF 후보 분류
→ 기존 블로그·기존 작업과 중복 검사
→ 프로젝트 품질 점수 계산
→ 원본 다운로드 및 서버 저장
→ 폰트·개인정보·페이지 품질 검사
→ 슬라이드 PNG 변환
→ 대표 슬라이드 자동 선정
→ 웹 전용 목업 합성
→ 포트폴리오 본문·FAQ·태그 작성
→ 문단 사이에 관련 이미지 배치
→ 비공개 검토 요청 등록
```

## 4. 시스템 구성

### 4.1 울림 홈페이지/Vercel

- NAVER WORKS 연결·해제 화면
- 탐색 대상 폴더 설정
- 동기화 시작과 최근 동기화 결과 확인
- 프로젝트 후보 목록과 선정·제외 사유 표시
- 자동화 일정과 검토 요청 표시

### 4.2 Supabase

- OAuth 토큰과 연결 상태
- Drive 파일 색인
- 프로젝트 후보와 중복 검사 결과
- 변환·목업·초안 작업 큐
- 변환 이미지와 완성 이미지 저장

OAuth 토큰은 브라우저나 공개 테이블에 노출하지 않고 서버 전용 권한으로만 접근한다.

### 4.3 문서 변환 작업 서버

Vercel에서는 무거운 PPT 렌더링을 직접 처리하지 않는다. 별도의 비동기 작업 서버가 다음 작업을 담당한다.

- PPT·PPTX·PDF 다운로드
- 폰트 목록 추출과 허용 폰트 대조
- 슬라이드별 PNG 렌더링
- 이미지 해상도·빈 페이지·깨짐 검사
- 개인정보 탐지용 이미지·텍스트 분석
- 웹 목업 이미지 합성

## 5. NAVER WORKS 인증 방식

Drive API는 서비스 계정 JWT가 아니라 **구성원 OAuth 인증**이 필요하다. `file.read` 읽기 전용 scope를 사용한다.

- Authorization URL: `https://auth.worksmobile.com/oauth2/v2.0/authorize`
- Token URL: `https://auth.worksmobile.com/oauth2/v2.0/token`
- Redirect URL: `https://woolim-site.vercel.app/api/admin/naver-works/callback`
- Access Token 만료 시 Refresh Token으로 자동 갱신
- Refresh Token 만료·권한 해제 시 관리자 화면에 재연결 알림

## 6. 데이터 구조

### `drive_connections`

- 공급자, 연결 사용자, scope
- 암호화된 access/refresh token
- token 만료일, 연결 상태, 마지막 오류

### `drive_roots`

- 탐색 대상 Drive 유형
- 사용자 ID, shared drive ID 또는 공유 폴더 ID
- root file ID, 표시 이름, 활성 여부

### `drive_files`

- file ID, parent ID, 경로, 파일명, 확장자
- 파일 크기, 수정일, fingerprint
- 동기화 상태, 지원 여부

### `portfolio_candidates`

- 프로젝트 폴더와 대표 원본 파일
- 중복 여부, 민감정보 위험도, 품질 점수
- 선정·제외·보류 사유

### `content_jobs`

- 다운로드, 변환, 검사, 목업, 글 생성 단계
- 대기·실행·완료·보류·실패 상태
- 재시도 횟수와 오류 기록

## 7. 프로젝트 자동 선정 기준

가점:

- PPT·PPTX·PDF 원본이 존재함
- 슬라이드 수와 이미지 해상도가 충분함
- 기획 구조와 시각적 차별성이 있음
- 지도, 도표, 정보구조, 실행 전략 등 다양한 화면이 있음
- 기존 블로그에 없는 업종·문서 유형임

감점 또는 제외:

- 기존 블로그 또는 기존 검토 초안과 중복
- 개인정보·고객 기밀 위험이 큼
- 폰트 누락으로 원본 재현이 어려움
- 이미지가 지나치게 저해상도임
- 완성본이 아닌 중간 작업 파일임
- 원본 내용만으로 프로젝트 설명이 불가능함

## 8. 폰트 처리

1. 원본 문서의 사용 폰트 목록을 추출한다.
2. 서버의 허용 폰트 목록과 비교한다.
3. 모두 있으면 변환한다.
4. 누락 폰트가 있으면 자동 대체하지 않고 보류한다.
5. 관리자가 허용한 대체 폰트가 등록된 경우에만 대체 변환한다.
6. 변환 전후 이미지 비교에서 글자 넘침·잘림이 발견되면 검토 요청에 올리지 않는다.

## 9. 단계별 구현

### 1단계 — Drive 연결 기반

- OAuth 연결·콜백·토큰 갱신
- 연결 상태 API
- DB 마이그레이션과 서버 전용 보안

완료 기준: 관리자 계정으로 한 번 승인하면 서버가 PC 없이 토큰을 갱신할 수 있다.

### 2단계 — 파일 색인과 후보함

- 지정 폴더 재귀 탐색
- PPT·PPTX·PDF 색인
- 변경 파일만 증분 동기화
- 관리자 후보 목록

완료 기준: 대표자가 파일을 찾지 않아도 시스템이 후보 프로젝트와 선정 사유를 표시한다.

### 3단계 — 변환·폰트·개인정보 검사

- 비동기 작업 큐
- 문서 변환 서버 연결
- 폰트 검사와 민감정보 위험 표시
- 변환 산출물 저장

완료 기준: 지원 가능한 파일은 슬라이드 PNG가 생성되고 문제 파일은 사유와 함께 보류된다.

### 4단계 — 목업·글·검토 요청

- 웹 목업 템플릿 합성
- 슬라이드 다양성 검사
- 본문 조사·작성
- 문단 사이 이미지 배치
- 검토 요청 등록

완료 기준: 대표 썸네일과 본문 목업, 글 전체가 관리자 검토 요청에 비공개로 등록된다.

### 5단계 — 예약 실행과 안정화

- 지정 일정 자동 동기화
- 실패 재시도와 알림
- 2~4주간 모든 결과를 검토 대상으로 운영
- 승인된 유형만 자동 제작 대상으로 확대

## 10. 대표자에게 필요한 작업

구현 중 다음 한 번의 승인이 필요하다.

1. NAVER WORKS Developer Console에서 OAuth 앱 생성
2. Redirect URL 등록
3. `file.read` scope 허용
4. Client ID와 Client Secret을 Vercel 환경변수에 저장
5. 홈페이지 관리자에서 `NAVER WORKS 연결` 버튼을 눌러 로그인·승인
6. 자동 탐색할 최상위 폴더 선택

Client Secret과 토큰은 채팅이나 화면에 붙여넣지 않고 Vercel 환경변수와 서버 전용 저장소에만 보관한다.

- 모든 단계 감사 로그 기록
