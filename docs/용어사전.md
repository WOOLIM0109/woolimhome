# 울림홈 프로젝트 용어사전

내 프로젝트에 **실제로 존재하는 것들만** 정리한 사전. 일반 개발 용어집이 아니라 `woolimhome` 전용.

---

## 1. 폴더 지도 — 어느 폴더에 뭐가 있나

가장 먼저 외울 것. "이거 고치려면 어디 가야 하지?"의 답.

| 폴더 | 뭐가 들어있나 | 이런 걸 고칠 때 여기로 |
|---|---|---|
| `app/` | **화면(페이지)** 전부 | 사이트에 보이는 글·버튼·배치 |
| `components/` | **재사용 부품** | 헤더, 푸터, 문의폼 등 여러 페이지에 공통으로 나오는 것 |
| `data/` | **내용물 데이터** | 회사명, 메뉴 이름, 서비스 목록, 통계 숫자 |
| `lib/` | **뒤에서 도는 로직** | AI 호출, 로그인 처리, 봇 판별 같은 안 보이는 기능 |
| `public/` | **이미지·폰트 파일** | 로고, 사진 교체 |
| `database/`, `supabase/` | **DB 설계도** | 데이터를 어떤 형태로 저장할지 |
| `scripts/`, `tools/` | **자동 실행 도구** | 배포, 점검용 스크립트 |
| `docs/` | **설명 문서** | (이 파일이 있는 곳) |
| `node_modules/` | **남이 만든 부품 창고** | ❌ 절대 손대지 말 것. 자동 생성됨 |
| `.next/` | **빌드 결과물** | ❌ 손대지 말 것. 자동 생성됨 |

### `app/` 안의 폴더 = 사이트 주소

Next.js는 **폴더 이름이 곧 URL**이다. 이게 핵심 규칙.

| 폴더 경로 | 실제 웹사이트 주소 |
|---|---|
| `app/page.tsx` | `woolim.com/` (메인) |
| `app/about/page.tsx` | `woolim.com/about` |
| `app/about/ceo/page.tsx` | `woolim.com/about/ceo` |
| `app/columns/page.tsx` | `woolim.com/columns` |
| `app/admin/page.tsx` | `woolim.com/admin` (관리자) |

> **"회사소개 페이지 문구를 바꾸고 싶다"** → `app/about/page.tsx` 열기. 끝.

`app/api/` 만 예외. 여긴 사람이 보는 화면이 아니라 **프로그램끼리 주고받는 창구**다.

## 2. 파일 확장자 — 이름 뒤에 붙은 글자

| 확장자 | 뜻 | 예시 |
|---|---|---|
| `.tsx` | 화면을 그리는 파일 (T**S** + **X**HTML) | `page.tsx` |
| `.ts` | 화면 없이 계산·처리만 하는 파일 | `schema.ts` |
| `.css` | 색·크기·간격 등 디자인 | `globals.css` |
| `.json` | 설정값 목록 | `package.json` |
| `.sql` | 데이터베이스 명령어 | `bot_traffic.sql` |
| `.md` | 그냥 문서 (사람용) | 이 파일 |
| `.mjs` | 실행용 스크립트 | `doctor.mjs` |

**규칙**: `page.tsx`라는 이름은 Next.js가 "이건 웹페이지다"라고 인식하는 **약속된 이름**. 마음대로 바꾸면 페이지가 사라진다. 같은 약속 이름: `layout.tsx`, `route.ts`, `middleware.ts`

## 3. 코드에서 계속 보이는 단어들

`app/page.tsx` 맨 위를 보면 이런 게 있다:

```tsx
import Link from "next/link";
import ContactBand from "@/components/ContactBand";
import { site, stats } from "@/data/site";

export default function HomePage() {
  return ( ... )
}
```

한 줄씩 풀면:

| 단어 | 뜻 | 쉽게 말하면 |
|---|---|---|
| `import` | 가져오기 | "다른 파일에 있는 걸 여기서 쓸게" |
| `from "@/components/..."` | 어디서 가져올지 | `@/` = 프로젝트 최상위 폴더 |
| `export default` | 내보내기 | "이 파일의 대표 결과물은 이거야" |
| `function` | 함수 | 재료를 넣으면 결과가 나오는 기계 |
| `return ( ... )` | 돌려주기 | "이 화면을 그려줘" — 괄호 안이 실제 화면 |
| `const` | 고정 변수 | 한 번 정하면 안 바뀌는 값 |
| `{ }` 안의 값 | 코드 삽입 | 글자 사이에 계산 결과를 끼워넣기 |

### 화면 부분에서 보이는 것들

```tsx
<Link href="/" className="flex items-center gap-3">
  <span>{site.name}</span>
</Link>
```

| 표기 | 뜻 |
|---|---|
| `<Link>` `<span>` `<div>` | **태그**. 화면 요소 하나. 반드시 `</Link>`로 닫음 |
| `href="/"` | **속성**. 태그에 주는 옵션 (여기선 링크 주소) |
| `className="..."` | **디자인 지정**. 색·크기·간격을 여기서 결정 |
| `{site.name}` | **변수 꽂기**. `data/site.ts`에 적힌 회사명이 여기 들어감 |
| `"use client"` (맨 윗줄) | "이 파일은 사용자가 클릭·입력할 수 있음" 표시 |

> **`{site.name}` 이게 중요하다.** 회사명이 코드에 직접 안 적혀 있고 `data/site.ts`에서 가져온다.
> 회사명을 바꾸려면 → `data/site.ts` 한 곳만 고치면 사이트 전체가 바뀜.

### className 읽는 법 (Tailwind)

`className`에 붙은 영어 조각들은 **디자인 명령어**다. 자주 나오는 것만:

| 조각 | 뜻 |
|---|---|
| `flex` | 가로로 나열 |
| `gap-3` | 요소 사이 간격 |
| `text-base` / `text-xs` | 글자 크기 (보통 / 아주 작게) |
| `font-bold` | 굵게 |
| `px-5` / `py-2` | 좌우 여백 / 위아래 여백 |
| `hidden` | 안 보이게 |
| `lg:flex` | **화면 넓을 때만** 가로 나열 (모바일 대응) |
| `bg-white` | 배경 흰색 |

숫자는 클수록 크다. `gap-3`보다 `gap-8`이 더 벌어짐.

## 4. 도구 이름 — 뭐가 무슨 역할인지

| 이름 | 정체 | 이 프로젝트에서 하는 일 |
|---|---|---|
| **Next.js** | 웹사이트 제작 틀 | 폴더를 주소로 바꾸고 페이지를 만들어줌 |
| **React** | 화면 조립 도구 | Next.js가 내부적으로 사용 |
| **TypeScript** | 프로그래밍 언어 | 오타·실수를 미리 잡아줌 (`.ts`/`.tsx`의 T) |
| **Tailwind** | 디자인 도구 | `className`에 적는 그 조각들 |
| **Supabase** | 데이터 보관소 | 문의내역·칼럼·회원정보 저장 |
| **Vercel** | 서버 | 사이트를 인터넷에 띄워주는 곳 |
| **Node.js** | 실행 엔진 | 내 컴퓨터에서 코드를 돌리는 프로그램 |
| **npm** | 부품 배달부 | 남이 만든 코드를 받아옴 (`node_modules/`에 쌓임) |
| **Git** | 변경 이력 관리 | 실수해도 되돌리기 |
| **GitHub** | Git 온라인 저장소 | 코드 백업 + Vercel이 여기서 코드를 가져감 |
| **VS Code** | 편집기 | 코드를 보고 고치는 창 |

### 흐름 한 줄 요약

```
내 컴퓨터에서 수정 → Git으로 저장 → GitHub에 올림 → Vercel이 감지 → 사이트 자동 갱신
```

## 5. 터미널 명령어 — 이 프로젝트에서 쓰는 것

VS Code에서 `Ctrl + ` `` 로 터미널을 연 뒤 입력.

| 명령어 | 하는 일 | 언제 |
|---|---|---|
| `npm run dev` | 내 컴퓨터에서 사이트 미리보기 | **수정 전에 항상 켜두기.** 저장하면 즉시 반영됨 |
| `npm run typecheck` | 문법 오류 검사 | 수정 후 |
| `npm run verify` | 검사 3종 한번에 | GitHub에 올리기 전 |
| `npm install` | 부품 내려받기 | 처음 세팅할 때 |

`npm run dev` 실행 후 브라우저에서 `localhost:3000` 열면 내 사이트가 보인다. **여기서 아무리 망가뜨려도 실제 사이트는 멀쩡하다.** 연습은 전부 여기서.

`Ctrl + C` 로 종료.

## 6. Git 용어 — 되돌리기의 언어

| 용어 | 뜻 |
|---|---|
| **repository (저장소, repo)** | 이 프로젝트 폴더 전체 |
| **commit (커밋)** | 저장 지점 하나. "여기까지 완성" 도장 찍기 |
| **branch (브랜치)** | 갈래. 본체를 안 건드리고 따로 실험하는 사본 |
| **main** | 본체 브랜치. 실제 사이트로 나가는 코드 |
| **push (푸시)** | 내 컴퓨터 → GitHub 업로드 |
| **pull (풀)** | GitHub → 내 컴퓨터 내려받기 |
| **staged** | 저장 예약된 상태 |
| **modified (M)** | 고쳤는데 아직 저장 안 한 상태 |
| **untracked (??)** | Git이 모르는 새 파일 |

| 명령어 | 하는 일 |
|---|---|
| `git status` | 지금 뭐가 바뀌었나 확인 |
| `git diff` | 뭘 어떻게 바꿨는지 상세히 |
| `git add .` | 바뀐 것 전부 저장 예약 |
| `git commit -m "설명"` | 저장 지점 만들기 |
| `git push` | GitHub에 올리기 |
| `git log --oneline` | 지금까지의 저장 지점 목록 |
| `git checkout -- 파일명` | 그 파일 수정 취소, 원래대로 |

## 7. 처음 수정할 때 안전 절차

```
1. git status          ← 깨끗한지 확인
2. npm run dev         ← 미리보기 켜기
3. 파일 수정 → 저장    ← 브라우저에서 바로 확인
4. npm run typecheck   ← 오류 없나 검사
5. git add .
6. git commit -m "무엇을 왜 바꿨는지"
7. git push            ← 실제 사이트 반영
```

**망했을 때**: `git checkout -- .` → 마지막 커밋 상태로 전부 복구.
커밋을 자주 할수록 되돌릴 지점이 많아진다. 하루에 여러 번 커밋해도 전혀 문제없음.

## 8. 손대면 안 되는 것

| 대상 | 이유 |
|---|---|
| `node_modules/` | 자동 생성. 지워도 `npm install`로 복구됨 |
| `.next/` | 빌드 찌꺼기. 자동 생성 |
| `package-lock.json` | 부품 버전 잠금표. 직접 편집 금지 |
| `.env.local`, `.env.production.local` | **API 키·비밀번호.** 절대 외부 공유 금지, GitHub 업로드 금지 |
| `.git/` | Git의 뇌. 날리면 이력 전부 소실 |
