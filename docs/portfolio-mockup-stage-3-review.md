# 묶음 3 검수 결과 — 로컬 자동 후보·수동 가림

2026-09-07 · 로컬 기능과 합성자료 검수 완료. 실제 업로드 연결·운영 설치·커밋·배포는 하지 않았다.

## 완성한 범위

`선정+예비 고해상도 PNG → PPTX 객체 기반 후보 → 원본 확대 확인·영역 편집 → 별도 PNG 생성·자동 검사 → 처리본 확대 확인·개별 승인`

- 정상 진입점 `initializePptxRedactions`는 실제 원본 바이트로 후보를 직접 계산한다. 원본·장표·제작 지문이 다르면 편집 기록을 만들지 않는다.
- 이메일·연락처·식별번호·계좌·인증정보·주소·인식된 QR/바코드/서명은 필수 불투명 가림 후보다. 이름·금액·내부 내용·일반 이미지·차트는 공개 범위를 직접 판단한다.
- 인접한 텍스트 런, 표 셀, 중첩 그룹, 레이아웃·마스터를 조사한다. 폰트 서식 때문에 분리된 이메일이나 눈에 보이지 않는 문자로 탐지가 빠지는 경우를 보강했다.
- 후보 기록에는 추출 원문 대신 분류 코드, 이유 코드, 원본 기준 0~1 좌표를 남긴다. 공개 예외에는 후보 ID와 허용한 사람·사유를 로컬에 보관한다.
- 일반 제목·도형을 전체 화면 블러하지 않는다. 필수 정보는 밝은 회색 불투명 마스크를 사용하며, 일반 수동 영역에는 강한 흐림도 선택할 수 있다.
- 편집기에서 사각형 추가·이동·우하단 핸들 크기 조절, 실행 취소·다시 실행, 처리 전후 비교를 지원한다.
- 확대는 원본 픽셀 기준 10~400%다. 100%에서 2400px 원본을 실제 2400 CSS px로 보여 주며 별도 화면 맞춤 버튼을 제공한다.
- 저장, 처리본 생성, 처리본 승인 버튼을 분리했다. 페이지 로드나 편집 중에는 자동으로 가림 결과를 생성/승인하지 않는다.
- 필수 후보를 단순 삭제하거나 약한 흐림으로 바꿀 수 없다. 후보를 완전히 덮는 불투명 구역 또는 사람·사유가 있는 명시적 공개 예외가 필요하다.
- 가림 후 디자인이 부적합하다고 선택하면 교체 필요로 보류한다. 기존 선정표로 돌아가 후보를 다시 고른다. 새 후보를 즉시 선택하는 웹 UI는 묶음 4에서 연결한다.

## 처리·보관·전송 경계

- 원본은 덮어쓰지 않는다. 출력과 수정 기록을 제작 폴더 안의 새 파일로 저장하고, 파일 지문을 검증한 뒤 원자적으로 기록을 갱신한다.
- 원본 이미지 지문, 작업/제작 ID, 장표 내용 지문, 규칙 버전, 영역·예외·검토 내용을 처리본 지문 키에 포함한다.
- 편집하면 해당 장표의 처리본 승인부터 무효화된다. 다른 장표는 유지된다. 내용이 같은 저장은 기존 처리본을 유지한다.
- 구역에는 긴 변 2400px 기준 6px 여유를 추가한다. 경계에서는 이미지 범위로 제한한다.
- 지정 구역 밖의 RGBA 값이 원본과 동일한지 전 픽셀 검사한다. 불투명 영역의 모든 픽셀도 확인한다. 픽셀 변경만으로 개인정보가 완전히 없다고 판정하지 않는다.
- 출력은 편집 레이어·EXIF·ICC·원문 메타데이터가 없는 평면 PNG다. 투명 원본 아래 숨은 RGB를 그대로 내보내지 않도록 투명 입력은 재변환을 요구한다.
- 처리본이 수정되거나 원본/선정/제작 기록이 바뀌면 이전 승인을 사용하지 않는다. 동시 저장은 수정 버전과 작업 잠금으로 충돌을 감지한다.
- 비용 보호를 위해 영역 수·누적 면적·흐림 개수를 제한한다. 실제 Gemini 또는 다른 유료 모델은 호출하지 않는다.
- `uploadVerifiedRedactedSlide`는 승인된 처리본의 PNG와 최소 식별 정보만 전달한다. 원본/미리보기/OCR/예외 메모/파일 경로는 전송 객체에 포함하지 않는다.
- 기본 네트워크 전송 구현은 없다. 명시적으로 주입한 전송 함수만 호출하며, 이번에는 대역만 사용했다. 자동 재시도는 없고 기본 제한 시간은 30초다. 실패한 업로드를 다시 명시 실행할 때 가림을 반복하지 않는다.
- 실제 업로드 구현은 같은 작업/제작/장표/가림 지문을 멱등 키로 쓰고 AbortSignal을 준수해야 한다. 이번 대역 결과를 운영 업로드 완료로 표시하지 않는다.
- 로컬 서버는 127.0.0.1, 서버별 HttpOnly 쿠키, 정확한 Host/Origin, 동일 출처, CSRF 토큰, 크기 제한된 JSON을 사용한다. 원본·편집 기록은 로컬 화면에서만 제공한다.

## 자동 탐지의 제한과 보류

- 픽셀 OCR·얼굴 인식 엔진을 연결하지 않았다. 이미지 내부의 글자·얼굴·라벨 없는 QR을 자동으로 전부 찾는 기능이 아니다. 모든 장표는 고해상도 수동 확인을 요구한다.
- PPTX 객체의 경계 상자를 사용한다. 렌더링된 글자 한 줄의 실제 외곽을 PowerPoint에서 측정하는 기능은 아직 없다. 가림 구역이 넓으면 로컬에서 검토하거나 다른 장표를 고른다.
- 텍스트 넘침/자동 확장, 상속·좌표 미확정, 추출 잘림/부분 실패는 강제 보류한다. 임의의 사각형 하나를 추가하거나 확인 체크만 해서 해제할 수 없다. 원본을 정리해 다시 변환하거나 해당 장표를 교체한다.
- 공개 예외의 검토자 이름은 로컬 사용자의 자기 기재이며 로그인 계정 인증/전자서명이 아니다. 운영 권한 연결은 묶음 5 범위다.
- 현재 서버의 기존 무블러 업로드 경로나 운영 워커를 교체하지 않았다. 새 로컬 경로를 검증한 뒤 전체 연결 단계에서 전환한다.
- Windows 재부팅, 실제 고객 자료의 공개 적합성, 실제 저장소 업로드는 이번 검수 대상이 아니다. 기존 파일 보관 만료/ACL 배포도 후속 연결 범위다.

합성 샘플은 고객 자료가 아닌 가짜 연락처·이메일·계좌·QR 모양·서명 문구다. 처음의 샘플 좌표가 글자 위쪽을 충분히 덮지 못하는 것을 시각검수에서 찾아 수정했고, 최종 3개 규격의 처리본을 각각 다시 열어 확인했다. 제목·일반 도형·색상 표식은 유지됐다.

PPTX 통합 테스트는 유효한 합성 OOXML에 대해 원본 검사 → 변환 대역 → 실제 후보 탐지 → 편집 → 가림/승인 → 업로드 대역을 검증한다. 화면 검수용 PNG는 코드로 만든 합성 자료이며 실제 PowerPoint 변환 검수와 혼동하지 않는다. 실제 PowerPoint 변환은 묶음 2 기록을 따른다.

## 실행

저장소 루트에서 비공개 작업 폴더와 원본을 지정한다. 환경변수 파일은 읽지 않는다.

```powershell
npm.cmd run prepare-local -- --source "<원본 PPTX 절대 경로>" --work-root "<짧은 로컬 비공개 작업 폴더>" --redact --serve
```

같은 원본·같은 작업 폴더로 재실행하면 정상 준비 파일과 편집 기록을 재사용한다. 실행 후 표시된 localhost 주소를 같은 PC에서 연다. 로컬 서버 종료는 해당 실행 터미널에서 Ctrl+C다. 다른 PC로 원본을 보내거나 Production을 자동 호출하는 옵션은 없다.

다음 묶음은 승인된 가림본을 고정 템플릿의 슬롯에 배정하고, 장표 교체·미리보기·최종 렌더를 연결하는 작업이다.
