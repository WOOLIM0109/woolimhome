# A4 입력 규격 호환 보완 검수

날짜: 2026-09-07  
범위: 로컬 코드·합성 시각 검수. 운영 배포·설치 워커 업데이트·실제 데이터 교체 없음.

후속 실제 검수: PowerPoint 사용 종료 후 두 실제 파일의 변환에 성공했다. 최신 결과와 남은 선별·가림 문제는 `docs/portfolio-mockup-a4-actual-review.md`를 따른다. 아래 변환 대기 기록은 호환 보완 당시의 상태다.

## 판정과 정정

사용자가 제공한 A4 가로 PPT는 잘못 설정된 파일이 아니다. PowerPoint의 A4 기본 슬라이드 크기는 27.517×19.05cm이고, 제공 파일의 `9906000×6858000 EMU`, `type=A4`가 이 설정과 일치한다. [Microsoft 공식 안내](https://support.microsoft.com/en-us/powerpoint/change-the-size-of-your-powerpoint-slides)

이전 검사는 종이 A4의 비율만 인정해 PowerPoint A4를 보류했다. 따라서 이전 묶음 5 보고서의 가로 규격 보류는 입력 오류가 아니라 지원 규격 차이에 따른 보류로 정정한다. 원본 파일을 다시 만들 필요는 없다.

세로 파일은 다른 경우다. `7775575×10907713 EMU`, type 미지정으로 약 21.5988×30.2992cm인 사용자 지정 규격이다. 가로 PowerPoint preset을 단순히 회전한 것으로 취급하지 않는다.

## 변경한 처리

- 원본 검사에 `pageSizeVariant`, `slideSizeType`를 기록하고, 정확한 PowerPoint A4 가로 preset을 기존 `a4_landscape` 세트로 분류한다.
- 단순히 모든 규격의 허용 오차를 넓히지 않았다. 알려진 preset과 일치하지 않는 사용자 지정 세로는 기본 경로에서 계속 보류한다.
- 원본 PPT와 승인된 가림 PNG는 수정하지 않는다.
- 가림 PNG 검증·승인 확인 후, 목업 렌더 입력에만 흰 바깥 여백을 더한다. 원본 픽셀을 복사하며 크기 변경·자르기·회전은 하지 않는다.
- 여백은 가운데 정렬한다. 홀수 1px가 남으면 오른쪽 또는 아래쪽에 둔다.
- 원본 승인 해시와 여백 보충 결과 해시, 원본/출력 크기, 여백 좌표, 처리 버전을 별도로 기록한다.
- 초안과 최종본이 같은 보충 규칙을 사용하는지 검사한다. 원본 승인 또는 처리 기록이 달라지면 이전 목업을 제공하지 않는다.
- 기존 템플릿 좌표·평행·각도·로고·배경·그림자·템플릿 버전은 변경하지 않았다. 입력 처리와 렌더 검증 버전만 갱신했다.
- 16:9 및 기존 엄격한 렌더 진입점의 기본 동작은 유지한다. 세로 사용자 지정 호환 옵션은 별도의 명시적 로컬 미리보기로만 시험하며 정상 승인·업로드 경로에 자동 등록하지 않는다.

가로 PNG가 2400×1662px이면, 템플릿 입력 캔버스를 2400×1698px로 확장한다. 원본 위·아래에 흰 여백 각 18px를 더하는 방식이다. 원본의 도형이나 글자를 눌러 맞추는 방식이 아니다. 실제 변환 PNG의 반올림 결과가 다르면 여백 픽셀 수를 그 크기에서 다시 계산한다.

## 안전 검사

- PNG 단일 이미지·크기·픽셀·불투명 여부 검사.
- 원본 규격에 맞는 PNG인지 확인. 방향이 반대이거나 1px 반올림 범위를 넘으면 거절.
- 원본 영역을 추출했을 때 픽셀이 보충 전과 완전히 같은지 검사.
- EXIF 회전, ICC·감마·색도·HDR 첨부처럼 표시 해석이 달라질 수 있는 입력은 보류. 텍스트 등 메타데이터는 결과에서 제거.
- 입력·결과 12MiB, 긴 변 4096px 상한.
- 같은 목업 안에서 원본 해시와 보충 결과 해시 각각 중복 검사.
- 가림 미승인 자료는 정상 목업 경로에서 계속 차단. 비율 처리가 가림 승인이나 최종 검수를 대신하지 않음.
- 정상 이미지 세트·본문·FAQ·제목·발행 정보는 이번 보완에서 변경하지 않음.

## 실제 파일과 시각 검수 구분

두 실제 파일의 저장된 규격을 수정된 검사로 다시 읽었다. 가로 30장은 `powerpoint_a4_preset_landscape / a4_landscape`, 세로 21장은 `custom / unknown`으로 구분됐다. 두 원본 해시는 이전 검사와 같다. 이 읽기 전용 확인은 실제 PowerPoint 이미지 변환·글꼴 시각 검수와 다르다.

실제 PowerPoint 변환은 이번 보완 턴에서 실행하지 않았다. 사용자는 창을 닫았다고 했지만 PowerPoint 프로세스가 남아 있었고, 다른 작업이 사용할 가능성을 알려주었다. 강제 종료·새 COM 연결·운영 워커 조작은 하지 않았다. 어느 프로그램이 사용하는지는 확인하지 않았다.

검사용 합성 장표로 A4 가로 5개, 사용자 지정 세로 비율 미리보기 5개를 생성했다. 실제 고객 PPT 목업이나 승인 완료본으로 표시하지 않는다. 생성 결과는 무시된 `.codex-tmp/a4-source-fit-qa/`에 두었다.

## 실행 기록

- 준비·가림·배치·이미지 세트·템플릿 잠금·렌더러·런타임·제목·A4 호환 관련 회귀 검사: 158개 통과, 실패 0개.
- `npm.cmd run typecheck`: 통과.
- `npm.cmd run lint`: 오류 0개. 기존 `ClientMarquee`의 `no-img-element` 경고 1개는 유지.
- `git diff --check`: 통과. 기존 파일의 LF→CRLF 안내만 출력됐으며 해당 파일은 정리하거나 다시 쓰지 않음.
- `scripts/render-a4-source-fit-qa.mjs`: 가로·세로 총 10개 템플릿의 초안/최종본 생성 및 일치 검사 통과. `results.json`에 `syntheticOnly: true`, `customerPowerPointConverted: false`로 기록.
- 최종 PNG 10개를 각각 눈으로 검수함. 썸네일·내지의 고정 좌표, 로고, 평행, 정렬과 바깥 여백 처리가 유지되는 것을 확인. 가로 BODY 2와 세로 BODY 4는 가이드선을 겹친 결과도 확인함.
- 합성 세로 입력 1711×2400px는 1711×2420px로 보충됨. 위·아래 10px씩 추가하며 원본 픽셀을 늘이거나 자르지 않음.
- 비교 이미지: `.codex-tmp/a4-source-fit-qa/fit-comparison.png`. 실제 고객 장표가 아닌 합성 검사용 이미지임을 이미지 안에도 표시함.

이 결과는 코드와 합성 이미지 검증이다. 실제 A4 고객 파일의 이미지 변환·폰트·가림 결과를 검수했다는 의미는 아니다.

## 남은 일

1. PowerPoint를 사용하는 다른 작업이 끝난 뒤 실제 A4 파일 변환을 재실행한다. 파일이나 프로세스를 임의로 변경하지 않는다.
2. 실제 가림 오탐·필수 후보를 해결하고 안전한 가림본으로 실물 목업을 확인한다.
3. 사용자 지정 세로는 이번 여백 시안 확인 후 작업별로 명시적인 호환 선택을 저장하는 절차를 연결한다. 모든 비슷한 세로 파일을 자동으로 승인하지 않는다.
4. 이전 묶음 5의 인증·운영 저장 경로 통합·DB 검증·복구·화면 일치 문제는 별도 미완료다.

이 보완을 묶음 5 전체 완료나 운영 배포 완료로 표현하지 않는다.
