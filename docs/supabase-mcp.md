# Supabase 읽기 전용 연결 (MCP)

작업하는 사람이 저장소 안에서 데이터를 직접 조회할 수 있게 하는 설정입니다.
설정 파일은 저장소 뿌리의 `.mcp.json` 입니다.

## 왜 넣었나

이 설정이 없던 동안, 무엇 하나 확인하려면 사람이 Supabase SQL 편집기를 열어
질의를 붙여넣고 결과를 다시 옮겨 와야 했습니다. 하루에 다섯 번을 그렇게 했고,
그 왕복이 길어지는 사이 잘못된 진단이 두 번 나왔습니다.

- 「밀린 글이 새벽에 예산을 먹는다」 → 로그를 보니 사실이 아니었음
- 「포트폴리오 후보가 말랐다」 → 후보가 21개 있었음

둘 다 데이터를 못 봐서 추측으로 메운 것입니다. 확인이 느리면 추측이 늘어납니다.

## 무엇을 넣어야 하나

환경변수 두 개입니다. **저장소에는 넣지 않습니다.**
Claude Code 웹의 환경 설정에 넣습니다.

| 이름 | 값 | 비밀인가 |
|---|---|---|
| `SUPABASE_ACCESS_TOKEN` | Supabase → Account Settings → Access Tokens 에서 발급 | **비밀** |
| `SUPABASE_PROJECT_REF` | 대시보드 주소의 `/project/` 뒤 문자열 | 아님(공개 URL 에 들어감) |

토큰은 발급 직후 한 번만 보입니다.

## 왜 `--read-only` 인가

이 연결은 **무엇이 잘못됐는지 보기 위한 것**이지 고치기 위한 것이 아닙니다.
쓰기까지 열어 두면, 조회하려던 손이 실수로 표를 바꿀 수 있습니다.
진단에 필요한 것은 읽기뿐이므로 그 이상을 주지 않습니다.

고치는 일은 지금까지처럼 마이그레이션과 코드로 합니다. 그래야 무엇을 언제
왜 바꿨는지가 저장소에 남습니다.

## 왜 `--project-ref` 를 함께 주나

계정에 다른 프로젝트가 있어도 이 프로젝트 하나만 보게 묶어 둡니다.
범위를 좁히는 데 드는 비용이 없으므로 좁혀 둡니다.

## 알아 둘 것

- **세션이 시작할 때 붙습니다.** 환경변수를 넣은 뒤 새 세션을 열어야 합니다.
  이미 열려 있는 대화에는 붙지 않습니다.
- `${...}` 치환이 통하지 않는 환경이면 `--project-ref` 는 값을 그대로 적어도
  됩니다. 비밀이 아닙니다. **`SUPABASE_ACCESS_TOKEN` 은 절대 그렇게 하지
  않습니다.**
- 조회한 내용은 대화 기록에 남습니다. `portfolio_candidates.project_name`,
  `column_expert_knowledge` 처럼 고객사 이름과 계약 내용이 들어 있는 표는
  필요한 칸만 골라 봅니다.
- `SUPABASE_SERVICE_ROLE_KEY` 는 이 용도로 쓰지 않습니다. 그것은 모든 표를
  읽고 쓰고 지울 수 있는 열쇠입니다. 서버(Vercel)에만 둡니다.

## 붙었는지 확인

새 세션에서 `/mcp` 를 치면 `supabase` 가 보여야 합니다.
쓰기를 시도하면 거부되어야 정상입니다.
