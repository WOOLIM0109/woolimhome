# 날짜·바닥글·쪽번호 자리는 마스터에서 찾는다

## 이어지는 작업

`02_슬라이드_밖_도형은_보류_사유가_아니다.md` 를 적용한 뒤 데브늄 원본을 다시 돌렸다.
보류가 41장 중 37장에서 **25장**으로 줄었다. 남은 25장은 원인이 하나 더 있다.

남은 것은 전부 같은 모양이다.

```
[text] key=slideLayout/2-sp meta="날짜 개체 틀 1"
[text] key=slideLayout/4-sp meta="슬라이드 번호 개체 틀 3"
```

레이아웃의 **날짜·바닥글·쪽번호 자리**다. 50개가 모두 위치를 못 찾았다.

## 원인

레이아웃에는 이 자리들의 `<a:xfrm>` 이 없다. 위치는 마스터에 있다.

```
slideLayout3.xml : <p:ph type="dt" sz="half" idx="10"/>      (xfrm 없음)
slideMaster1.xml : <p:ph type="dt" sz="half" idx="2"/>       <a:off x=838200 y=6356350/>
```

`lib/pc-worker/preparation/pptx-inspection.ts` 의 `exactPlaceholder` 는
`idx` 가 있으면 **`idx` 로만** 짝을 찾는다. 레이아웃은 `idx="10"`, 마스터는 `idx="2"` 라
짝이 없다고 보고 빈손으로 돌아온다. 그래서 `shapeTransform` 의 마스터 되돌아보기가
무의미해지고, 위치를 못 읽은 것이 되어 `GEOMETRY_UNRESOLVED` 가 붙는다.

`idx` 는 그 문서 안에서만 쓰는 번호다. 날짜·바닥글·쪽번호·머리글 네 자리는
문서를 건너뛸 때 **종류(type)로** 이어받는 것이 맞다. 본문·제목 자리는 지금처럼
`idx` 로 이어받아야 하므로 그쪽은 건드리면 안 된다.

## 고칠 것

### `lib/pc-worker/preparation/pptx-inspection.ts` 의 `exactPlaceholder`

기준이 되는 `ph` 의 종류가 `dt`, `ftr`, `sldNum`, `hdr` 넷 중 하나이면
**`idx` 를 보지 않고 종류로만 짝을 찾는다.** 그 밖의 종류는 지금 그대로
`idx` 우선, 없으면 종류로 찾는다.

지금처럼 **짝이 꼭 하나일 때만** 쓴다. 둘 이상 나오면 지금처럼 빈손으로 돌아가
`GEOMETRY_UNRESOLVED` 가 붙는다. 그 안전장치는 그대로 둔다.

### 시험

`lib/pc-worker/preparation/pptx-inspection.test.mjs` 에 더한다.

- 레이아웃의 `dt`(`idx="10"`, xfrm 없음)가 마스터의 `dt`(`idx="2"`, xfrm 있음)에서
  위치를 이어받아 `rect` 가 나오고 `GEOMETRY_UNRESOLVED` 가 붙지 않는다
- 같은 종류가 마스터에 둘 이상이면 여전히 위치를 못 찾고 `GEOMETRY_UNRESOLVED` 가 붙는다
- 본문 자리(`body`)는 종류가 같아도 `idx` 가 다르면 이어받지 않는다

## 건드리지 말 것

- `INHERITED_PLACEHOLDER_VISIBILITY_REQUIRES_LOCAL_REVIEW` 경고는 그대로 둔다.
  날짜·쪽번호에 실제로 **무엇이 찍히는지**는 여전히 PowerPoint 로 그려봐야 안다.
  이번에 고치는 것은 **어디에 찍히는지**뿐이다.
- `hasFatalRedactionWarning` 의 판정 목록과 지문 확인은 그대로 둔다.
- 런타임 꾸러미를 다시 만들거나 설치하지 않는다.
