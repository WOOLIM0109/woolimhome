# 과업 · 세로 4:3 장표를 포트폴리오로 쓸 수 있게 한다

상태: **대기** (2026-11-07 기록)

## 왜 필요한가

「에너제닉_ 회사소개서 리디자인」을 자동 제작에 걸었더니 변환 단계에서 거절됐다.

```
NON_PRESENTATION_LAYOUT: Slide ratio 0.75 is not 16:9, 4:3, A4 landscape, or A4 portrait.
```

0.75 는 4:3 을 세로로 세운 비율이다(19.05 × 25.4cm). 대표는 A4 세로로 알고 있었으나
A4 세로는 0.707(21 × 29.7cm)이라 6% 차이가 난다. 허용 오차는 2.5% 다.

**파일 잘못이 아니다.** 우리가 받는 규격에서 세로 4:3 이 빠져 있다.
지금 허용 목록은 이렇다 — A4 는 가로·세로를 다 받는데 4:3 은 가로만 받는다.

| 규격 | 받는가 |
|---|---|
| 16:9 가로 | O |
| 4:3 가로 | O |
| A4 가로 | O |
| A4 세로 | O |
| **4:3 세로** | **X** |

세로 4:3 은 회사소개서·제안서에서 흔한 규격이다. 이 한 건으로 끝날 문제가 아니다.

## 왜 한 줄로 못 고치나

막는 자리가 세 군데다.

1. `tools/woolim-pc-worker/worker.ps1` 의 `Test-SupportedPageRatio` — 허용 비율 네 개
2. `lib/pc-worker/preparation/pptx-inspection.ts` 의 `classifyPreparationPageSize` — 같은 네 개
3. **목업 보드가 없다.** `lib/portfolio/approved-mockup-suites.ts` 가 가진 보드는
   `16:9`, `a4_landscape`, `a4_portrait` 뿐이고 PSD 틀은 `16:9`, `4:3` 가로용뿐이다.
   비율만 통과시키면 그다음 단계에서 「얹을 틀이 없다」로 다시 멈춘다.

### 쉬운 길은 쓰지 않기로 했다

`lib/portfolio/a4-source-fit.ts` 가 A4 보드에 여백만 넣어 원본을 얹는다.
세로 4:3(19.05 × 25.4cm)은 A4 세로(21 × 29.7cm) 안에 확대·잘라내기 없이 들어간다.

그런데 그 함수는 비율 차이를 3% 까지만 받는다(`CUSTOM_RATIO_OUTSIDE_PREVIEW_LIMIT`).
이 건은 6% 라 거절된다.

**그 3% 를 늘려서 통과시키지 않는다.** 원본과 다른 모양으로 나가는 것을 막는 장치다.
가림 검사와 같은 종류라, 숫자를 무르게 해서 여는 것은 고치는 게 아니다.

## 할 일

세로 4:3 전용 보드를 만들어 규격을 하나 더 받는다. 디자인 결정이 들어간다.

1. 세로 4:3 목업 보드(대표 1장 + 본문 4장) 디자인 — 대표 확인 필요
2. `approved-mockup-suites.ts` 에 aspectClass 추가
3. 1·2번 두 파일의 허용 비율 목록에 추가
4. 보드별 검사 추가

## 같이 되돌릴 것

아래 두 건은 이 과업 때문에 막혀서 제외했다. 보드가 생기면 후보로 되돌린다.

- 「에너제닉_ 회사소개서 리디자인」 (2026-11-07 제외, 세로 4:3)

## 이 과업에 넣지 않는 것

같은 날 나온 **가림(블러) 보류**는 별개다. 2026-11-08 에 원인을 찾아 고쳤다(PR #220).

「240618 데브늄 사업제안서(파랑 ver.)」이 41장 중 37장에서 `GEOMETRY_UNRESOLVED` 로
막혔던 것은 위치를 못 읽어서가 아니라, 위치를 알고 있는데도 못 읽었다고 본 경우였다.
원인이 둘이었다.

1. 디자이너가 쓰다 남긴 글상자·그림을 **슬라이드 밖에 치워두고** 작업한 파일이었다.
   화면 밖 도형은 그림으로 내보낼 때 그려지지도 않는데 보류 사유가 되고 있었다.
2. 레이아웃의 **날짜·바닥글·쪽번호 자리**는 위치가 마스터에 있는데,
   둘을 잇는 `idx` 번호가 서로 달라 짝을 못 찾았다.

둘 다 고친 뒤 같은 원본에서 보류가 0장이 됐다. 판정 함수와 지문 확인은 건드리지 않았다.
