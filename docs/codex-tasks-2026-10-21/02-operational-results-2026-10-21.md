## 오늘 실패한 공고의 원인과 복구

「2026년 스타트업 법률지원사업 울산광역시 법률상담회 참여 기업 모집 안내」는 HWPX·PDF 2/2 추출에 성공했지만 **Gemini 응답의 JSON·근거 검증 단계**에서 실패했다. 당시 응답 종료 사유가 보존되지 않아 원인을 `MAX_TOKENS`로 확정할 수 없다. 출력량 7,996/8,000은 출력 제한 압박의 정황일 뿐이다. canonical 요건 저장에는 도달하지 않았다.

구조화 JSON·낮은 thinking·출력 상한 16,000·응답 선저장·단계별 진단을 반영하고, 관리자 화면에서 같은 원문·같은 모델의 명시적 1회 복구를 실행했다. 2026-10-21 **13:59:28.636 KST**에 HTTP 200·`STOP`·출력 1,111로 추출됐고, 13:59:31.984에 469개 대상 매칭까지 완료했다. 원래 실패 시도는 보존했다. 실제 PDF 3쪽 중 **2쪽**의 일반 창업 7년·신산업 10년 예외를 확인했다. 이 조건을 무조건적인 7년 상한으로 저장하지 않고 숫자는 null, 실제 조건 문장은 basis에 보존했다.

확대 검사에서 발견한 별도 PDF 3건은 **글자 추출 후 DB 저장 단계**의 문제였다. 유효한 PDF의 추출문에 U+0000이 포함되어 PostgreSQL text 저장이 거부됐고, 기존 통합 오류 메시지가 이를 다운로드/저장 실패로 표시했다. 원본 SHA-256 3/3 일치를 확인하고 NUL 문자만 제거해 정확한 공고·첨부 ID·해시·실패 상태·시도 수 조건으로 복구했다. 원본·해시·시도 이력은 유지했으며 총 8,930자를 저장했다. 재발 방지 코드는 NUL 제거, 제거 후 빈 문서의 no_text 처리, 단계별 고정 오류 코드를 포함한다. 페이지 표식과 다른 문자는 보존한다.

v3 보정 도중 **15:23:43 KST의 배치 1회**는 Gemini가 아닌 **대상별 매칭 저장 SQL**에서 중단됐다. 운영 Postgres 로그에서 SQLSTATE `57014`·statement timeout·`save_openchat_program_matches`의 전체 선정 해제 UPDATE임을 확인했다. 기존 함수가 공고마다 당일 매칭 26,264행을 모두 false로 다시 쓰고 선정 공고를 true로 바꾸는 방식이 원인이었다. 실패 거래는 롤백되어 기존 매칭은 보존됐다.

다섯 번째 마이그레이션은 동일한 순위·자격 조건·8개 상한을 계산한 뒤 **선정 값이 실제로 바뀌는 행만 갱신**한다. 요건 버전·검토 날짜·원문 확인 시각의 매칭 완료 표식을 함수 끝에서 같은 거래로 확정하므로, canonical 요건 갱신 후 매칭 저장이 실패해도 다음 실행의 재처리 대상에서 빠지지 않는다. 56×469행 실제 PGlite 회귀에서 초기 선정 변경 3,744행·동일 결과 재저장 0행, 실패 롤백·같은 버전/같은 해시의 원문 확인 갱신 후 재개를 확인했다. 기존 3인자 함수·잠금·RLS·ACL은 유지한다. 이 배치 실패 1회와 최종 요건 레코드 실패 수는 다른 지표다.

## 처리 방식과 제한

관리자 실행은 **1회 최대 100건·작업 240초**다. 새 Gemini 생성은 남은 시간이 60초 이상일 때만 시작하며 요청 최대 80초와 저장 여유 25초를 적용한다. 남은 작업은 다음 실행에서 이어간다. 실제 운영 배치는 시간 한도 안에서 약 10건씩 새로 추출했으며, 기존 2건 상한을 제거했다.

동일 원문 실패를 자동 유료 재호출하지 않는다. 비공개 원응답을 파싱 전에 저장하고, 일반 실행과 명시적 복구를 별도로 기록한다. 기존 일일·월간 호출 수와 비용 상한은 유지한다. 정상화 버전 2·3 보정은 기존 응답과 같은 입력 해시를 재사용해 추가 모델 호출 없이 반영했다.

## 원문 확보의 남은 제한

지원 문서 HWP/HWPX/PDF와 이미지·TXT·미확인 형식·ZIP 컨테이너를 구분한다. 스캔 PDF에 OCR을 수행했다고 보고하지 않는다. 동국대 시설 사진 PDF 1개는 기존 30MB 제한으로 건너뛰었다. HC20 서명 HWP 1개는 일반 HWP5(OLE) 형식이 아니며 현재 추출기가 처리할 수 없어 원본을 보존했다. HC20을 손상·DRM으로 단정하지 않는다. 표준 PDF/HWPX 원문 확보 또는 해당 형식 식별 후 별도 추출기 검토가 수정안이다.

공고 76건에 대한 조회·탐색을 마쳤다는 사실과, 모든 공고의 원문을 완전히 읽었다는 주장은 구분한다. 남은 입력 부족은 추가 Gemini 예산만으로 해결되지 않는다.

## 최종 무작위 10건의 원문 대조

요건 추출을 끝낸 56건에서 10건을 **한 번만** 추첨해 고정했다. 중간 성공 11건에서 뽑았던 파일럿과 구분하며, 문제를 발견한 뒤에도 같은 10건을 유지했다. 보정 전 입력·JSON과 감사 결과는 보존하고 최종 저장 정본은 별도 파일로 대조한다.

보정 전 비null 값 221개는 PDF 쪽 근거 65개, HWP/HWPX/HTML 문단 근거 156개였고 출처·유일 locator·실제 인용의 불일치는 0개였다. 그럼에도 의미 감사에서 남구의 무조건 7년 상한과 공주대의 가점 총상한 누락을 발견했다. PR #157은 이를 v3로 보수적으로 보정한다. 인용 일치와 조건 전체를 빠짐없이 추출했다는 주장은 다르다.

원본 PDF가 있는 8건은 DB 원본 SHA 대조·렌더링·시각 확인을 마쳤다. 공주대 HWP는 K-Startup 공식 Synap 9쪽 렌더 중 실제 1·3·4쪽을 확인했다. 마지막 디자인 공모전은 [발행기관 공식 공고](https://www.bsia.or.kr/announcements/68?mcode=an011)의 PDF를 별도로 확보해 HWP 인용 8개를 실제 1·2·3쪽과 대조했다. 이 추가 PDF는 교차검증 자료이며 기존 첨부 DB를 바꾸거나 새 모델 입력으로 넣지 않았다. **공고 단위 물리 페이지 교차 확인 10/10**이다.

## 평일 오전 자동 실행 설정

오늘 검증 뒤 `/api/cron/program-review`의 UTC 표현식 `*/2 23 * * 0-4`, `*/2 0 * * 1-5`를 추가한다. **한국 평일 08:00–09:58, 2분 간격**이며 공휴일은 함수에서 건너뛰고 휴일 확인 실패도 실행을 허용하지 않는다. 겹친 실행은 전역 lease로 건너뛰며, 일일 고객 캐시 확인·미처리 요건·미완료 매칭을 다음 회차에서 이어간다. 동일 원문·이미 호출한 실패를 자동 유료 재시도하지 않는다.

기존 **13개 경로·표현식은 그대로**이며 신규 표현식 2개를 더해 총 15개다. 원래 11개 수집·초안·승인·발행 등의 시간과 첨부 2개 시간도 보존한다. `node scripts/verify-program-review-crons.mjs vercel.json`이 정확한 기존 13쌍 및 14일 20,160분을 검증해 평일 10일×60회=600회·주말 0회를 확인했다. 실제 운영 반영의 main SHA·READY·도메인·크론 15개 확인값은 [최종 반영 PR #158](https://github.com/WOOLIM0109/woolimhome/pull/158)의 배포 검증 기록과 최종 응답에서 확인한다.
