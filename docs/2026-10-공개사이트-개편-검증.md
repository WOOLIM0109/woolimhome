## 실적·화면·텍스트

- 원장 합계: 정부지원사업 **23건 / 21억 4,959만**, 입찰 **5건 / 26억 5,000만**, 투자 **1건 / 2억**. 총액은 **49억 9,959만**, 억 단위 내림 표기는 **49억+**다.

- 화면은 `getSuccessLedger()`와 집계 함수를 사용한다. 원장 배열은 외부에 내보내지 않는다.

- `/`, `/about`, 성공사례 5개 화면, 포트폴리오 3개 화면, 서비스 2개 화면, `/llms.txt` 등 총 13개 경로의 200 응답을 확인했다. 새 성공사례 경로는 사이트맵에도 포함된다.
- 삭제한 네 경로의 308 응답과 각 대체 목적지를 확인했다. `app/cases`, `app/projects` 디렉터리는 제거했다.
- 포트폴리오 50개 카드의 실제 이미지 장수, 이니셜 `alt`, 프로젝트 제목을 응답 HTML과 대조했다.
- 고객사 식별은 상호 비교 없이 `clientKey`로 한다. 이니셜과 회사 업종은 수동 지정했으며, 프로젝트 업종은 별도로 유지했다. 서로 다른 키의 표기 충돌, 동일 키의 일관된 표기, 원장·포트폴리오 키의 유효성을 테스트했다.
- 미래아이앤택·미래아이엔텍은 `mirae`의 실명·별칭으로 묶었다. 실명·별칭 목록은 `server-only` 경계 안에 두고 공개 데이터에는 전달하지 않는다.
- 공개 지정 포트폴리오 기관 4곳과 발주처·입점처의 실명을 유지했다. 지정된 익명화 대상 상호는 확인한 페이지 원본·JSON-LD·브라우저 JavaScript에서 발견되지 않았다. 소스의 실명 목록은 요청한 `data/clients.ts`에만 보관한다.
- `이미지시안/`은 보존하고 `.gitignore`에 추가했다. 지정된 루트 `Codex 이미지 …png`는 삭제했다. 이미지 내용 점검·가림·교체는 수행하지 않았다.

현재 Windows 작업 경로의 `#` 문자 때문에 원본 경로의 Turbopack·Webpack 빌드가 경로 해석 오류로 실패했다. 환경변수 파일을 제외한 동일 코드·의존성을 `#` 없는 임시 폴더로 복사해 **Next 16.3 Turbopack 프로덕션 빌드**를 통과시켰고, 그 빌드의 로컬 HTTP 응답을 확인했다. 프로젝트 빌드 설정은 변경하지 않았다.

## 상담 수신 — 코드 테스트 결과

상담 관련 테스트 15개가 통과했다. DB·외부 응답을 대체한 테스트이며 실제 서비스 수신 검증과 구분한다.

| 조건 | 코드 테스트 결과 |
|---|---|
| 정상 접수 | 모의 DB에 한 행 저장 → 200 → 응답 이후 메일·구글폼 병행, `notified_at` 기록 |
| Resend 키 누락 | 저장·200·구글폼 병행 유지, `notify_error` 기록 |
| 메일 실패 | 개인정보를 포함하지 않는 오류 사유 기록 |
| DB 저장 실패 | 502, 후속 발송 작업 등록 없음 |
| 허니팟 | 행 생성·외부 호출·속도 제한 소모 없이 200 |
| 속도 제한 | 시간당 10회 유지, 초과 시 429와 `Retry-After` |
| 복수 수신처·회신 | SDK가 두 수신처와 `reply_to`, 접수별 중복 방지 키를 직렬화하는지 확인 |
| 본문 | 이름·연락처·이메일·유입 경로·세부 항목·문의 원문·한국 날짜 포함 |
| 구글폼 | 기존 폼 ID·필드·토큰 제출 유지, 메일과 독립 실행, 각 외부 요청에 시간 제한 |

실제 Next 서버에서도 입력 오류 400, 허니팟 200, DB 설정을 비운 경우 502를 확인했다. 현재 단일 문의 폼의 기존 항목을 저장 갈래로 매핑하며, 새 문의 화면이나 전용 문항은 추가하지 않았다.

## 상담 수신 — 실제 DB·메일 확인 여부

**실제 DB 저장, 실제 `notified_at`/`notify_error` 갱신, 두 수신함의 메일 수신은 확인하지 않았다.** 요청 범위가 코드까지이므로 마이그레이션을 원격 DB에 적용하지 않았고 테스트 메일·구글폼 실제 제출도 하지 않았다. SQL의 RLS·권한은 코드 검토 대상이며 실제 DB에서 실행 검증한 결과가 아니다.

운영 적용 시 마이그레이션, Supabase·Resend 환경변수, 발신 도메인 인증과 실제 수신 확인이 남아 있다. 구글폼 코드는 유지했으며, 병행 운영 2주 후 건수 대조와 제거는 후속 작업이다. 공개 지정 기관의 계약 확인도 배포 전에 별도로 필요하다.
