# 이모지 글꼴 이름을 설치된 이모지 글꼴로 알아본다

작업 폴더: `C:/dev/woolimhome/.codex-tmp/emoji-font` (브랜치 `fix/worker-emoji-font-alias-20261107`)

## 지금 무슨 일이 일어나고 있나

사무실 PC 워커가 포트폴리오 원본 PPT 를 열고 글꼴을 확인하다가 여기서 멈췄다.

```
MISSING_FONTS: PowerPoint cannot find these source fonts: color-emoji.
```

`color-emoji` 는 윈도우에 설치할 수 있는 글꼴이 아니다.
웹에서 만든 자료(구글 슬라이드·캔바 등)를 PPTX 로 내보내면 이모지 글자에 이런 이름이 붙는다.
그래서 「글꼴 설치 후 다시 처리」를 눌러도 같은 자리에서 또 멈춘다.

이모지는 글자가 아니라 그림이다. 윈도우 기본 이모지 글꼴로 그려도 모양이 달라지지 않는다.

## 할 일

`tools/woolim-pc-worker/worker.ps1`

- `Get-WorkerFontAliases` 가 설치된 글꼴 이름을 모은 뒤,
  **이모지 글꼴이 실제로 깔려 있을 때만** 아래 이름들을 같은 목록에 더한다.
  - `color-emoji`
  - `coloremoji`
  - `color emoji`
  - `noto color emoji`
  - `apple color emoji`
  - `segoe ui emoji`
  - `twemoji mozilla`
  - `emojione`
  - `joypixels`
- 「이모지 글꼴이 깔려 있다」는 설치된 글꼴 이름 중 `emoji` 가 들어간 것이 하나라도 있는 경우로 본다
  (윈도우에는 보통 `Segoe UI Emoji` 가 있다).
- 이모지 글꼴이 하나도 없으면 지금처럼 빠진 글꼴로 보고한다. 조용히 넘기지 않는다.
- 이름 비교는 지금처럼 대소문자를 가리지 않고, `Get-NormalizedWorkerFont` 를 거친 값으로 한다.
- `MISSING_FONTS:` 문구와 다른 글꼴의 동작은 그대로 둔다.

왜 이렇게 하나: 진짜로 빠진 글꼴을 놓치면 장표가 엉뚱한 글자로 나온다.
그래서 「확인을 끄는」 방식이 아니라 「설치된 이모지 글꼴이 이 이름을 대신한다」로 만든다.

## 검사

`lib/pc-worker/worker-fonts.test.mjs` 에 더한다. 이미 `worker.ps1` 의 함수를 실제로 불러 쓰는 틀이 있으니 그것을 쓴다.

1. 설치 목록에 `Segoe UI Emoji` 가 있으면 `Get-WorkerFontAliases` 결과가 `color-emoji` 를 담는다
2. 설치 목록에 이모지 글꼴이 하나도 없으면 `color-emoji` 를 담지 않는다
3. 이모지 글꼴이 있어도 `Work Sans SemiBold` 처럼 상관없는 이름은 그대로 빠진 글꼴로 남는다

윈도우가 아닌 환경에서는 지금 파일이 하는 대로 건너뛴다.

끝나면 `npm run verify` 를 돌리고, 실패한 검사 이름과 오류 원문을
`docs/codex-tasks-2026-11-07/02-emoji-font-results.txt` 에 적는다.

## 지키는 선

- `.codex-tmp/` 안의 다른 폴더는 건드리지 않는다
- 워커의 버전 번호(`$WorkerVersion`)는 올린다. 사무실 PC 가 스스로 새 파일을 받아 가야 한다
- 글꼴 확인 자체를 끄거나 건너뛰는 길을 만들지 않는다
- 유료 글꼴 정책(`lib/portfolio/font-policy.ts` 의 `UNOWNED_PAID_FONT_FAMILIES`)은 건드리지 않는다
- SQL·마이그레이션은 건드리지 않는다
