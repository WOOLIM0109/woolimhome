# 꾸러미를 올려두고 PC가 받아가게 한다

## 지금 무엇이 막는가

`bridge-update.cmd` 는 **그 PC에서 꾸러미를 직접 만든다.** 그래서 재료 폴더
(`node_modules`)가 그 PC에 있어야 한다. 사무실 PC의 워커 코드 폴더에는 없다.

```
PREPARATION_DEPENDENCY_MISSING
필요한 부품 폴더(node_modules)가 없습니다.
```

직원 PC도 같은 벽을 만난다. 가림 편집 한 가지 때문에 PC마다 개발 재료를
몇백 MB씩 깔 이유가 없다.

**꾸러미를 설치하는 쪽은 재료가 필요 없다.** `scripts/install-preparation-runtime.mjs`
와 `scripts/preparation-runtime-package.mjs` 는 Node 기본 기능만 쓴다(확인함).
만들 때만 재료가 든다.

그래서 **만드는 일은 우리가 하고, PC는 받아서 확인만 한다.**

## 만들 것

### 1. 꾸러미를 올리는 쪽 (우리 PC에서만 쓴다)

`scripts/publish-preparation-runtime.mjs` 를 새로 만든다.

- 꾸러미를 만든다(`packagePreparationRuntime`)
- 그 폴더를 zip 으로 묶는다
- 화면에 이 셋을 낸다 — **꾸러미 지문**, **zip 파일의 SHA-256**, zip 경로
- GitHub 에 올리는 일은 **하지 않는다.** 사람이 `gh release` 로 올린다.

### 2. 승인 목록에 받는 곳을 적는다

`tools/woolim-pc-worker/approved-preparation-runtimes.json` 의 각 항목에
두 칸을 더한다. 둘 다 없어도 되는 칸이다(옛 항목은 그대로 둔다).

```json
{
  "fingerprint": "…",
  "version": "1.0.0",
  "platform": "win32",
  "arch": "x64",
  "note": "…",
  "url": "https://github.com/WOOLIM0109/woolimhome/releases/download/…/preparation-runtime-1.0.0-<지문앞8자>.zip",
  "archiveSha256": "…"
}
```

`approved-runtime.mjs` 의 검사에 더한다 — `url` 이 있으면
`https://github.com/WOOLIM0109/woolimhome/releases/download/` 로 시작해야 하고,
`archiveSha256` 은 64자 16진수여야 한다. 하나만 있고 다른 하나가 없으면 잘못된
목록으로 본다. 이 저장소 주소가 아니면 받지 않는다.

### 3. PC가 받아서 설치한다

`tools/woolim-pc-worker/bridge-update.ps1` 에 받는 길을 더한다.

승인 목록의 최신 항목에 `url` 이 **있으면** 이 순서로 한다.

1. 빈 새 폴더에 zip 을 받는다 (`WoolimWorker\staging\<시각>`)
2. **받은 zip 의 SHA-256 을 `archiveSha256` 과 맞춘다.** 다르면 그 자리에서
   멈추고 지운다. 열어보지 않는다.
3. 맞으면 푼다 (`Expand-Archive`, 비어 있는 새 폴더에만)
4. 지금처럼 `install-preparation-runtime.mjs --expected-fingerprint <승인 지문>` 으로
   설치한다. 꾸러미 내용 검사는 그대로 거친다.
5. 그다음은 지금과 같다 — 시험 실행, `bridge-runtime.json` 전환, 다시 시작,
   결과 확인, 실패하면 되돌리기

`url` 이 **없으면** 지금처럼 그 PC에서 만든다(재료가 있는 PC용). 기존 길을 지운다.

새 오류 문구:
- `PREPARATION_ARCHIVE_DOWNLOAD_FAILED` → `설치 파일을 받지 못했습니다. 인터넷 연결을 확인해 주세요.`
- `PREPARATION_ARCHIVE_SHA_MISMATCH` → `받은 설치 파일이 승인된 것과 다릅니다. 설치하지 않았습니다.`

### 4. 저절로 받아가게 한다

`tools/woolim-pc-worker/bridge-launch.ps1` 이 띄우기 전에 한 번 본다.

- 승인 목록의 최신 지문이 `bridge-runtime.json` 의 지문과 **같으면** 그냥 띄운다
- 다르고, 그 항목에 `url` 이 있으면 3번 순서를 밟는다
- **어느 단계에서 실패하든, 지금 쓰던 꾸러미로 그냥 띄운다.**
  업데이트가 안 됐다고 가림 편집이 멈추면 안 된다. 이유는 `bridge-launch.log` 에 남긴다
- 이미 편집 중인 요청(`state: review`)이 있으면 바꾸지 않고 그냥 띄운다.
  열린 편집 화면을 끊지 않는다. 다음에 확인할 때 다시 본다

## 건드리지 말 것

- `scripts/preparation-runtime-package.mjs` 의 `PREPARATION_RUNTIME_SOURCE_FILES`
  **새 파일을 넣지 않는다.** 넣으면 꾸러미 지문이 바뀐다.
- 수정 금지 파일 (10-28 문서의 「공통 지키는 것」) 그대로.
- 지문 확인을 건너뛰는 길을 만들지 않는다. 자동으로 **하는** 것이지 **빼는** 것이 아니다.
- 승인 목록에 없는 지문은 어떤 경우에도 설치하지 않는다.
