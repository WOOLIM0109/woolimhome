# 묶음 5 — 실사용 PPT 검사와 이미지 교체 연결 검수

후속 검수에서 세 가지 로컬 문제 수정과 같은 실제 PPT 3종의 완성 목업 15장 검수를 완료했다. 최신 판정과 남은 승인 사항은 [로컬 재검수 완료 보고서](portfolio-mockup-local-retest-complete.md)를 따른다. 아래는 최초·중간 검사 당시의 기록이다.

날짜: 2026-09-07  
판정: **부분 진행·보류. 전체 흐름 합격 또는 운영 투입 가능 상태가 아니다.**

최신 실제 A4 검수: 가로 30장 미리보기·16장 고해상도 변환, 세로 별도 진단 21장 미리보기·4장 확대 변환에 성공했다. 가림 승인과 완성 목업은 아직 미완료이며 `docs/portfolio-mockup-a4-actual-review.md`에 현재 결과를 기록했다. 아래 최초 검사 표와 변환 대기 상태는 당시 기록이다.

후속 정정: 실제 가로 파일은 정상적인 PowerPoint A4 preset이다. 종이 A4 비율만 지원했던 검사 기준을 보완했다. 세로는 별도 사용자 지정 규격이며, 자세한 변경·합성 검수·실물 변환 대기 상태는 `docs/portfolio-mockup-a4-compatibility-review.md`를 따른다. 아래 표는 최초 실물 검사 당시의 기록이다.

### 발견하고 수정한 장수 판독 오류

PowerPoint의 실제 장표 목록뿐 아니라 구역 목록에 저장된 `p14:sldId` 참조까지 세던 문제가 있었다. 이로 인해 장수가 두 배가 되거나 존재하지 않는 장표를 손상 장표로 오판할 수 있었다.

`pptx-inspection.ts`의 검사와 가림 추출 경로를 실제 presentation 바로 아래의 유일한 `p:sldIdLst` 목록만 읽도록 수정했다. 구역 참조를 무시하는 경우와 실제 장표 목록이 중복되어 모호한 경우의 회귀 테스트를 추가했다. 원본 PPT를 다시 작성하는 수정은 아니다.

### 아직 수정하지 않은 가림 탐지 문제

선택된 10장 전부가 현재 불확실성 규칙에 걸린다. 읽기 전용 구조 검사와 PowerPoint 표시 상태 확인으로 원인을 구분했다. 원문이나 무블러 고객 이미지를 외부 모델에 보내지 않았다.

이는 경고 세 종류를 문자열로 일괄 무시해도 된다는 뜻이 아니다. 원본 12번의 필수 서명 후보, 9·10번의 금액 후보, 회전·뒤집기·그룹·표·사진 내부 확인은 별도로 남아 있다. 실제 렌더된 텍스트 경계를 검증하거나 안전한 로컬 편집 절차로 해결한 다음 다시 검사해야 한다.

현재 `originalInspected`·최종 승인 체크를 대신 켜거나, 검사하지 않은 장표를 승인본처럼 목업에 넣지는 않았다. 따라서 이번 실제 파일로 완성한 목업 세트와 Codex 최종 이미지 시각 검수 결과는 아직 없다.

## 3. 로컬에서 준비한 연결 코드

### 새 장표 준비 요청

기록된 새 장표 요청을 명시적으로 실행하는 로컬 CLI 경로를 추가했다. 필요한 장표만 고해상도로 변환하고 가림 편집 상태를 만든다. 기존 선택·목업·활성 세트를 유지하고, 실패 시 이미 만든 정상 파생파일부터 다시 쓸 수 있다.

요청이 생겼다는 이유로 자동 실행하거나 자동 가림 승인하지 않는다. 관리자 화면·운영 작업 큐·설치된 워커에는 아직 연결하지 않았다.

### 최종 5장 전달과 본문 보존

`mockup-handoff.ts`와 `image-set.ts`에 주입형 로컬 전달·세트 교체 경로를 준비했다.

1. 현재 원본·제작 시도·규격·템플릿·슬롯 배정·가림 승인과 최종 PNG 5장의 지문을 확인한다.
2. 초안·원본·원문·로컬 경로·공개 예외 기록은 전달 명세에서 제외한다.
3. 최종 확인 해시가 현재 세트와 일치해야 전달할 수 있다.
4. 5장 모두 새 경로에 쓰고 다시 읽어 지문·PNG 크기를 확인한다.
5. 전부 성공한 뒤 이미지 세트와 본문 이미지 주소를 한 번에 바꾸도록 저장소 계약을 호출한다.
6. 중간 업로드나 마지막 저장이 실패하면 기존 세트·원고는 유지한다. 새 경로의 부분 파일은 다음 명시적 재시도를 위해 남긴다.

현재 실제 저장소 대신 메모리 대역을 주입해 검증했다. 운영용 불변 파일 저장 구현, 인증된 서버 경로와 실제 Postgres 검증까지 끝난 상태가 아니다. SQL 마이그레이션 파일은 준비만 했고 적용하지 않았다.

### PC 실행 위치 독립성

승인 목업 렌더러가 현재 작업 폴더에 의존하지 않고 필요한 코드·로고·배경·폰트를 찾도록 런타임 목록과 패키징 검사를 추가했다. 파일·구현·Sharp 버전 지문 불일치와 패키지 밖 경로를 차단한다.

이는 완성된 PC 워커 설치 패키지가 아니다. Node/Sharp 및 전체 준비 경로 배포, 작업 큐·설치 스크립트 통합은 남아 있다. 기존 템플릿의 좌표·각도·배경 디자인은 바꾸지 않았다. 렌더 구현 지문은 바뀌므로 이전 초안·최종 PNG는 재검증/재제작 대상이 된다.

## 5. 운영 연결 전 반드시 해결할 문제

1. **실제 PPT의 가림 오탐과 미확정 경계:** 위 숨김 필드/일반 자동맞춤 오탐을 고친 뒤, 실제 민감 후보의 경계와 가림 결과를 확인해야 한다. 경고 제거만으로 통과시키지 않는다.
2. **A4 규격 처리:** 정확한 A4 파일 제공 또는 명시적으로 승인한 비율 보정 규칙이 필요하다. 보정한다면 원본 내용은 늘리지 않고, 별도 파생 이미지의 변환 좌표·규격·지문을 일관되게 기록해야 한다.
3. **승인자와 대상 작업의 인증:** 전달 함수의 문자열·boolean은 인증 증명이 아니다. 서버가 인증된 관리자 ID·서버 시각을 부여하고, 작업 ID와 원본 해시·제작 시도를 서버 발급 작업/수신 증명으로 결합해야 한다. 임의 작업 ID로 다른 포트폴리오에 붙일 수 있게 노출하면 안 된다.
4. **기존 저장 경로와의 충돌:** 기존 수동 업로드·job runner·worker 완료 경로에는 리뷰 이미지를 직접 지우고 넣는 코드가 남아 있다. 새 교체 함수가 원자적이어도 이 경로들이 같은 잠금/계약을 쓰지 않으면 이미지·본문 주소·활성 세트가 어긋날 수 있다. 새 세트가 활성화된 작업에서는 차단하거나 한 경로로 통합해야 한다.
5. **동일 세트 재시도의 무결성:** 현재 동일 활성 세트의 빠른 성공 반환은 이미지 목록·본문 이미지 주소·리뷰 행까지 모두 일치하는지 검사하지 않는다. 다른 경로가 바꾼 뒤 재시도해도 성공처럼 보일 수 있어, 불일치 검사와 명시적 복구가 필요하다.
6. **실제 DB·저장소 검증:** 준비한 SQL 함수는 인증/최종 이미지 검증기 전체가 아니다. 서버가 검증된 명세로만 저장 요청을 구성해야 한다. 실제 Postgres 실행·경쟁 상태·실패 복구와 업로드 불변성·시간 제한을 별도로 시험해야 한다.
7. **첫 교체 전의 기존 세트 복구:** 새 방식으로 등록된 세트 간 복구는 테스트했지만, 기존 방식의 첫 세트를 그대로 복구하는 API/화면은 아직 없다. 기존 메타데이터·리뷰 행 백업만으로 복구 기능 완료라고 표시하지 않는다.
8. **운영 화면과 워커 연결:** 로컬 승인과 서버 승인, 관리자·검토·외주·다운로드의 동일 세트 조회, 워커 버전/지원 기능 협상, 사용자 최종 승인 화면이 남아 있다.

기존 수동 이미지 경로는 삭제 후 등록을 각각 수행하고, 마지막 조건부 갱신이 0행인 경우를 충분히 확인하지 않으며, 본문 이미지 주소 동기화도 새 계약과 다르다. 기존 재생성 경로는 상태·요약·검토 메모까지 변경할 수 있다. 이 경로들을 새 기능에 그대로 연결하지 않았고 이번에 운영에서 실행하지 않았다.
