# 흥국생명 테마 글꼴·별칭 오류 수정

기존 PC 변환 워커는 `+mn-ea`, `+mj-ea`를 설치 글꼴 이름으로 비교하고, 설치된 `맑은 고딕`의 영문 별칭 `Malgun Gothic`을 인식하지 못했다. 새 워커는 PPTX의 presentation → slide → layout → master → theme 관계를 따라 장표 ID별 테마를 읽는다. major/minor의 ea 선언이 비어 있으면 해당 텍스트와 언어 정보에 맞는 Hang/Jpan/Hans/Hant 선언을 사용한다. 설치 글꼴은 현재 이름과 영문·한글 별칭을 같은 family로 비교한다.

혼합 서식 텍스트의 각 run, 중첩 그룹, 표 셀을 검사한다. 기존처럼 글꼴 조사 중 예외를 무시하지 않는다. 알 수 없는 토큰, 해석 불가능한 테마, 지원하지 않는 themeOverride, 외부·중복 관계, 경로 이탈, DTD·외부 엔티티와 과도한 XML은 거부한다. 구형 바이너리 PPT에서 XML 테마를 확인할 수 없는 토큰도 임의로 설치됨 처리하지 않는다. 하나라도 Test 이름을 가진 family는 별칭 전체를 설치 목록에서 제외한다. 유료 글꼴 정책은 변경하지 않는다.

워커 버전은 `2.10.1`로 올렸다. 기존 자동 업데이트가 새 파일을 인식하도록 하기 위한 변경이다. 승인 전에는 운영 워커에 설치하지 않으며, 실행 중 워커의 원본 폴더와 다른 worktree에서 구현·테스트했다. 별도 다운로드 진단 PR도 워커 버전을 변경하므로 두 번째 PR 병합 전 main 반영과 최종 버전 확인이 필요하다.

검증: PowerShell 함수만 AST로 추출해 실행하는 글꼴 테스트 6건과 기존 워커 잠금 테스트 3건이 통과했다. 실제 PC 사용자 환경의 설치 글꼴 목록에서도 `Malgun Gothic=true`, `맑은 고딕=true`, Test 별칭 0개를 확인했다. 이 확인은 글꼴 목록 조회이며 PowerPoint 실행·원본 변환·운영 작업 재요청은 하지 않았다. 실제 흥국생명 원본의 변환 성공까지 검증한 결과는 아니다. 운영 후보는 수정 승인 전까지 `excluded`로 유지한다.

Microsoft 근거: [FontFamily.GetName](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.fontfamily.getname), [PowerPoint NameFarEast](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.font.namefareast). 구현의 장표별 관계 해석과 보수적 거부 조건은 이 저장소의 오류 재현 및 테스트에 근거한다.

커밋 전 `npm run verify`: 타입·린트와 1,016 통과·Unix 전용 5 생략·실패 0 (`.codex-tmp/verify-theme-fonts-installed.log`). 최초 독립 worktree 검증은 로컬 node_modules 부재로 패키징 11건이 `PREPARATION_DEPENDENCY_MISSING`으로 실패했으며, 잠금 파일 그대로 `npm ci --ignore-scripts` 후 전체 재검증했다. 패키지 버전·잠금 파일·보안 검사는 변경하지 않았다. 새 PowerShell 실행 테스트 5개는 Windows에서 실제 실행하며 Ubuntu에서는 해당 환경 의존 테스트로 생략한다.
