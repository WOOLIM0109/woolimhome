# 설치 스크립트가 같은 사용자를 다른 사람으로 본다

## 무슨 일이 있었나

2026-11-08, 사무실 PC에서 `tools/woolim-pc-worker/bridge-install.ps1` 을 처음
돌렸더니 이 줄에서 멈췄다.

```
다른 Windows 사용자의 편집 연결 작업입니다. 워커를 설정한 사용자로 로그인해 주세요.
```

**같은 사용자다.** 이 PC에서 확인한 값은 이렇다.

```
기존 작업의 Principal.UserId : 설비빔
[Security.Principal.WindowsIdentity]::GetCurrent().Name : 미성\설비빔
같은 계정의 SID              : S-1-5-21-3283427931-2639871843-2856447757-1001
```

윈도우는 로컬 계정으로 예약 작업을 등록하면 컴퓨터 이름을 떼고 **계정 이름만**
저장한다. `install.ps1` 이 만든 변환 워커 작업도 `설비빔` 으로 저장돼 있다.

`bridge-install.ps1:20-24` 는 `$existing.Principal.UserId` 를 `$identity.Name`
(`미성\설비빔`)과 `$identity.User.Value`(SID) 두 가지와만 비교한다. 둘 다 아니므로
같은 사람인데 남으로 본다.

**그래서 이 스크립트는 두 번째 실행부터 언제나 막힌다.** 자기가 등록한 작업도
`설비빔` 으로 저장되기 때문이다. 다시 깔거나 고쳐 깔 수 없다.

## 고칠 것

`tools/woolim-pc-worker/bridge-install.ps1` 의 그 비교 한 군데다.

이름끼리 맞춰보는 대신 **계정 번호(SID)로 맞춘다.**

- `$existing.Principal.UserId` 를 SID 로 바꿔 본다. 그 값은 세 가지 모양일 수 있다 —
  `설비빔`(계정 이름만), `미성\설비빔`(컴퓨터\계정), `S-1-5-...`(SID 문자열).
  `System.Security.Principal.NTAccount` 의 `Translate` 와, 이미 SID 모양이면
  `SecurityIdentifier` 로 바로 읽는 길을 둘 다 둔다.
- 바꾼 SID 가 `$identity.User.Value` 와 같으면 같은 사용자다. 그대로 진행한다.
- 다르면 지금처럼 막고 같은 한국어 문구를 보인다.
- **SID 로 바꾸지 못하면**(계정이 지워졌거나 알 수 없는 이름) 막는다. 모르면 막는 쪽이다.
- `UserId` 가 비어 있으면 지금처럼 그냥 진행한다.

`install.ps1` 은 고치지 않는다. 그쪽은 기존 작업을 보지 않는다.

## 시험

`lib/pc-worker/bridge-installation.test.mjs` 에 더한다.

- `UserId` 가 **계정 이름만**(`설비빔`)일 때 같은 사용자로 보고 진행한다
- `UserId` 가 `컴퓨터\계정` 일 때도 진행한다
- `UserId` 가 **SID 문자열**일 때도 진행한다
- 정말 다른 사용자면 지금처럼 막고 문구가 같다
- SID 로 바꾸지 못하는 이름이면 막는다

## 건드리지 말 것

- 덮어쓰기 전 `_replaced` 로 복사해 두는 동작
- 돌고 있는 프로세스를 끄지 않는 동작
- 예약 작업 등록 방식과 `PT5M` 재확인
- 승인 지문 목록과 그 검사
