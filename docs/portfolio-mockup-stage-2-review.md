# 묶음 2 검수 결과 — 로컬 PPTX 준비와 작업 기록

2026-09-07 · 로컬 구현·합성자료 검수 완료. 운영 연결·설치·커밋·배포는 하지 않았다.

## 이번에 완성한 범위

`PPTX 읽기 전용 검사 → 전체 저해상도 후보 → 선정·제외표 → 선정+예비만 고해상도 → 로컬 확인`

- 원본 전체 바이트의 SHA-256, 작업 UUID, 제작 UUID를 기록한다. 이름만 바뀌어도 같은 작업 폴더와 같은 바이트면 재사용한다.
- 원본·폰트 환경·변환기 코드·검사/선정 코드·PowerPoint 버전이 바뀌면 새 제작 기록으로 분리한다.
- 원본 순서의 1-based 장표 번호를 유지한다. 숨김·빈 장표·손상·규격·미확정 글꼴을 구분한다.
- 실제 placeholder/layout/master/theme 상속, 그룹, 표의 글꼴을 조사한다. 확정하지 못한 글꼴/개체는 추측해서 통과시키지 않는다.
- 비율 오차 허용은 0.5%다. 16:9/A4 가로/A4 세로만 승인 템플릿으로 진행한다. 4:3과 기타 규격은 보류한다.
- 숨김·빈 장표·손상처럼 명시적으로 제외한 장표를 빼고 긴 변 800px 미리보기를 만든다.
- 선별은 구조·구성·대표성·다양성·가림 후 가독성을 근거로 하는 **보조 규칙**이다. 미적 완성도나 문서 의미를 이해하는 AI 평가가 아니다.
- 사진/표 밀도, 누락 폰트, 완전 중복, 검사 불가 개체를 선정에서 제외한다. 평면 일러스트를 사진으로 일괄 제외하지 않는다.
- 기본 선정 상한은 14장, 예비는 남은 적격 후보 중 최대 2장이다. 최소 고유 장수는 고정 템플릿 정의에서 가져온다: 16:9 8장, A4 가로/세로 7장.
- 부족한 장표를 억지로 반복하거나 규격을 늘려 맞추지 않는다. 명시적인 번호 선별은 `--select`로 바꿀 수 있다.
- 선정+실제 예비만 긴 변 2400px로 변환한다. PNG 해독·크기·비율·단색 빈 이미지·번호·지문을 확인한다.
- 파일 한 장이 정상 저장될 때마다 기록한다. 중간에 멈추면 다음 실행에서 정상 파일만 재사용한다.
- 현재 사용 중인 결과 참조와 제작 중인 기록은 분리한다. 이 경로에서는 활성 결과를 변경하지 않는다.

## 로컬 보관과 실행 안전장치

- 기존 `worker.ps1`, 설정, `.env` 파일, 서버 DB, Gemini 클라이언트를 가져오지 않는 별도 진입점이다.
- 원본은 저장하지 않는다. PowerPoint에는 지문을 검증한 읽기 전용 사본만 열고 매크로를 비활성화한다.
- 기존 PowerPoint가 열려 있으면 멈춘다. 사용자 문서를 닫거나 프로세스를 강제 종료하지 않는다.
- 자기 PowerPoint의 종료를 제한 시간 동안 확인한 뒤 다음 변환을 시작한다.
- PowerShell 프로세스는 3분 제한이다. 종료와 진행 중인 저장 콜백이 끝난 다음에만 작업 잠금을 놓는다. 자동 재시도는 없다.
- ZIP 크기/압축 해제량/파일 참조, 외부 미디어, 매크로, 잘못된 XML을 변환 전에 차단한다.
- 작업 경로는 실제 경로로 확인한다. 동기화 폴더 이름, 링크/junction, 원본과 작업 폴더의 상호 포함을 차단한다.
- Windows PowerPoint 호환성을 위해 작업 루트는 100자 이내의 짧은 로컬 폴더를 사용한다.
- 로컬 확인 서버는 `127.0.0.1`에만 연결한다. 서버별 HttpOnly 쿠키·동일 출처·Host 검사를 하고 등록된 PNG만 지문 확인 후 제공한다.
- 자동 삭제/보관 만료 정책과 Windows 계정별 ACL 배포 구성은 운영 연결 단계에서 마무리한다. 현 단계에서 임의의 공유 폴더를 사적인 폴더로 바꿔 주는 기능은 없다.

PowerPoint 실제 버전: `16.0.20326.20132`. 고객 파일 대신 합성자료만 사용했다. 발표자료 스킬의 제작·패키지 검증 절차로 검사 자료를 만들고, 최종 파일을 실제 PowerPoint로 변환해 확인했다.

테스트를 하며 OPC의 정상적인 패키지 절대 경로, Windows PowerShell의 `Get-FileHash` 모듈 자동 로드, 긴 경로, PowerPoint의 비동기 종료, 화면의 선정 사유 덮어쓰기 문제를 수정했다. 재시도만으로 숨기지 않고 해당 경로를 다시 확인했다.

## 직접 실행할 때

프로젝트 루트에서 아래 형식을 사용한다. 원본과 다른, 본인 PC의 동기화되지 않는 로컬 폴더를 지정한다.

```powershell
npm.cmd run prepare-local -- --source "<원본.pptx>" --work-root "C:\Users\becky\AppData\Local\WoolimWorker\preparation\작업이름" --serve
```

같은 작업을 다시 실행할 때 `--work-root`를 그대로 유지한다. 번호를 직접 고를 때는 `--select 1,3,4,6,8,10,12,14`처럼 지정한다. 중복·누락·검사 실패 장표는 강제로 통과되지 않는다.

확인 화면은 원본 번호·선정/예비/제외 사유·이미지를 읽는 **시제품**이다. 블러 편집 버튼은 다음 묶음용으로 비활성화되어 있다. 진행/실패 정보는 실행 콘솔과 디스크의 단계 기록에서 확인한다. 원본을 여는 웹 버튼과 운영 상태 동기화는 아직 연결하지 않았다.

## 남아 있는 범위

- 이 준비 경로는 `.pptx` 전용이다. `.ppt`, `.pptm`, PDF 자동 정규화는 미구현이며 원본을 임의로 변환·저장하지 않는다.
- 표 스타일 간접 글꼴·일부 복합 문자권·OLE/영상·해석 불가 미디어·임베디드 글꼴은 보수적으로 보류한다.
- 자동 점수/이미지 검사만으로 폰트 대체, 모든 글자 누락, 디자인 품질을 보장하지 않는다. 완료 상태도 `ready_for_local_review`이며 공개 승인 상태가 아니다.
- PC를 실제 재부팅하지는 않았다. 별도 프로세스 재실행과 디스크 기록 재개·죽은 소유자 잠금 복구로 검증했다.
- 무블러 자료는 여전히 PC 안의 준비물이다. 자동·수동 블러와 블러본 검증은 **묶음 3**, 슬롯 배정 UI는 **묶음 4**, 운영 워커/관리자/외주 화면 연결은 **묶음 5**다.
